    Retrieves the ways a location can be verified.

    Google decides which options a location is eligible for, and each option
    says what it needs. Call this before Start Verification to find out what to
    offer the site owner.

    For a service-area business, save `serviceAreaPostalAddress` on the location
    first with Update Location. Google can't work out the options without it.

    Pass `languageCode` to get the option text in the site owner's language.
    It defaults to English.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.PROMOTE.MANAGE-SEO">Manage SEO Settings</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/gbp/v1/locations/{locationId}:getVerificationOptions
    ```

    ## Path Params

    <ParamField path="locationId" type="string" required>

      Location ID. This is Google's location identifier.

    </ParamField>

    ## Body Params

    <ParamField body="languageCode" type="string">

      BCP-47 language code the option text should come back in, such as `he` or
      `fr`. Google localizes what it returns for the merchant-facing option
      (for example the ADDRESS option's expected recipient text). Leave it out
      to get English. Optional.

      Constraints: `maxLength 35`.

    </ParamField>

    ## Response Object

    <ResponseField name="options" type="VerificationOption[]">

      Verification methods available for this location.

      <Expandable title="options properties">

        <ResponseField name="method" type="string">

          The verification method.

          **Supported values:**

          - `ADDRESS` — Postcard to the business address
          - `EMAIL` — Email with a PIN
          - `PHONE_CALL` — Automated phone call with a PIN
          - `SMS` — SMS with a PIN
          - `AUTO` — Google-side instant verification (e.g. domain ownership)

        </ResponseField>

        <ResponseField name="displayData" type="string" deprecated>

          Deprecated: read the method-specific `data` fields instead.
          Flattened display string: the phone number (PHONE_CALL/SMS), the email
          address (EMAIL), or a single-line postal address (ADDRESS). Empty for AUTO.

          **Deprecated.** Deprecated: read the method-specific `data` fields instead.
          Flattened display string: the phone number (PHONE_CALL/SMS), the email
          address (EMAIL), or a single-line postal address (ADDRESS). Empty for AUTO. Use `data` instead. Removal: 2026-11-30. Constraints: `maxLength 255`.

        </ResponseField>

      </Expandable>

    </ResponseField>

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `500` | `INTERNAL` | `GOOGLE_API_CALL_FAILED` |  |
    | `400` | `INVALID_ARGUMENT` | `INVALID_VERIFICATION_ADDRESS` | Google rejected the request with HTTP 400. The location's service-area postal address is the only caller-supplied input to this call, and Google returns no reason token to discriminate on, so a 400 means that address needs fixing — prompt the merchant to correct it (UpdateLocation with field_mask = "service_area_postal_address") and retry. |
