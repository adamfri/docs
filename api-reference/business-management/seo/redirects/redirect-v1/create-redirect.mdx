    Creates a redirect.

    The `from` path can't be the site root, and can't already belong to another redirect unless
    `options.forceReplace` is `true`. With `options.forceReplace`, the redirect that holds the path
    is deleted and the new one is created in its place.

    If the redirect would close a loop, meaning an existing redirect starts at the path this one
    points to, the redirect that closes the loop is deleted and the create proceeds. Both a
    conflicting redirect replaced this way and a loop-closing redirect are gone for good, so
    retrieve them first if you need to restore them.

    Creating a redirect that already exists with the same `from`, `to`, and `options.groupRedirect`
    changes nothing and returns the redirect from the request, without an `id` or a `createdDate`.

    To create multiple redirects in a single API call, call [Bulk Create Redirects](https://dev.wix.com/docs/api-reference/business-management/seo/redirects/redirect-v1/bulk-create-redirects). Note the
    difference in how the two handle problems: this method resolves loops and, with
    `options.forceReplace`, conflicts, while [Bulk Create Redirects](https://dev.wix.com/docs/api-reference/business-management/seo/redirects/redirect-v1/bulk-create-redirects) fails the individual redirect
    instead.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Body Params

    <ParamField body="redirect" type="Redirect" required>

      Redirect to create.

      See the [Redirect Object](/api-reference/business-management/seo/redirects/redirect-v1/redirect-object) for this object's fields.

    </ParamField>

    <ParamField body="options" type="CreateRedirectOptions">

      Extra options for creating the redirect.

      <Expandable title="options properties">

        <ParamField body="forceReplace" type="boolean">

          Whether to delete the redirect that already starts from the same `from` path and create the new
          one in its place. When `false`, a taken `from` path fails the call with `FROM_URL_EXISTS`.

          The replaced redirect is deleted for good, so retrieve it first if you might need to restore it.

          Default: `false`

        </ParamField>

      </Expandable>

    </ParamField>

    ## Response Object

    <ResponseField name="redirect" type="Redirect">

      Created redirect.

      `createdDate` isn't returned. When the site already has an identical redirect, the redirect from
      the request is returned as is, without an `id`.

      See the [Redirect Object](/api-reference/business-management/seo/redirects/redirect-v1/redirect-object) for this object's fields.

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `400` | `INVALID_ARGUMENT` | — | The `redirect` is missing, or one of its fields is invalid. The `from` path can't be the site root. Details are in `fieldViolations`. |
    | `409` | `ALREADY_EXISTS` | `FROM_URL_EXISTS` | There's already a redirect from this `from` path. Nothing is written. The existing redirect's `from`, `to`, and `options` are returned in the error's `data`. To replace it, set `options.forceReplace` to `true`. |

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>

    ## Examples

    A group redirect carries the rest of the URL over to the target, so `/forum/questions/my-post` resolves to `/forum/faqs/my-post`. A trailing slash is dropped from the stored `from` path, and `createdDate` isn't returned. Call Get Redirect to retrieve it.

    <CodeGroup>

      ```bash Request
      curl -X POST \
      'https://www.wixapis.com/seo-redirects-service/v1/create-redirect' \
      -H 'Authorization: <AUTH>' \
      -H 'Content-Type: application/json' \
      -d '{
        "redirect": {
          "from": "/forum/questions/",
          "to": "/forum/faqs/",
          "options": { "groupRedirect": true }
        }
      }'
      ```

      ```json Response
      {
        "redirect": {
          "from": "/forum/questions",
          "to": "/forum/faqs/",
          "options": {
            "groupRedirect": true
          },
          "id": "583fe7d7-2944-436f-870a-09eb6d2e52fa"
        }
      }
      ```

    </CodeGroup>
