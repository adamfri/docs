---
title: "Project Object"
description: "A project pairs a marketplace provider with the client who submitted a brief requesting their services."
icon: "cube"
---

A project pairs a marketplace provider with the client who submitted a brief requesting their
services. It tracks the engagement from first contact through delivery, including the agreed
budget, the client's review, and proof of what was delivered.

Projects are created as part of the marketplace matching flow, so there's no method for creating
one. A provider advances a project with Start Project, Complete Project, and Cancel Project.

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Project ID.

    </ResponseField>

    <ResponseField name="revision" type="integer">

      Revision number, which increments by 1 each time the project is updated. To prevent conflicting
      changes, the current revision must be passed when updating the project.

    </ResponseField>

    <ResponseField name="createdDate" type="datetime">

      Date and time the project was created.

      **Read-only.**

    </ResponseField>

    <ResponseField name="updatedDate" type="datetime">

      Date and time the project was updated.

      **Read-only.**

    </ResponseField>

    <ResponseField name="serviceName" type="string">

      Marketplace service the project is attributed to.

      To set this value, specify `serviceName` when calling Complete Project.

      **Read-only.**

      **Supported values:**

      - `UNKNOWN_SERVICE_NAME` — No service, or an unrecognized service.
      - `DOMAIN` — Connect or set up a domain.
      - `ACCESSIBILITY` — Improve site accessibility.
      - `RESTAURANT_MENU_SETUP` — Set up a restaurant menu.
      - `STORE_OPTIMIZATION` — Optimize an online store.
      - `ADVANCED_WEBSITE` — Build an advanced website.
      - `CUSTOM_INPUT_FORMS` — Build custom input forms.
      - `SITE_GUIDANCE` — Guidance on building a site.
      - `ECOMMERCE_SITE` — Build an eCommerce site.
      - `ADS` — Set up and manage ads.
      - `PROFESSIONAL_TRANSLATION` — Professional content translation.
      - `BRAND_DEVELOPMENT` — Develop a brand.
      - `EMAIL` — Set up business email.
      - `CUSTOM_SITE_FUNCTIONALITIES` — Build custom site functionalities.
      - `THIRD_PARTY_SERVICES` — Integrate third-party services.
      - `VISUALS` — Create visual assets.
      - `CODING_GUIDANCE` — Guidance on custom code.
      - `EMAIL_MARKETING` — Set up email marketing.
      - `WRITTEN` — Written content.
      - `PHOTOS` — Photography.
      - `STORE_SETTINGS` — Configure store settings.
      - `ANALYTICS` — Set up analytics.
      - `CLASSIC_WEBSITE` — Build a classic website.
      - `PIXEL` — Set up a tracking pixel.
      - `REDESIGN_SITE` — Redesign an existing site.
      - `MOBILE_APP` — Build a mobile app.
      - `CONTENT_WITH_DATABASE` — Build content backed by a database.
      - `UPDATES` — Site updates and maintenance.
      - `INSTALL_APPS` — Install and set up apps.
      - `MOBILE_SITE` — Optimize the mobile site.
      - `LOGO` — Design a logo.
      - `CUSTOM_DESIGN` — Custom design work.
      - `ADVANCED_STORE` — Build an advanced store.
      - `SEO` — Search engine optimization.
      - `MOVE_SITE` — Move a site to Wix.
      - `EDIT_IMAGE` — Edit images.

    </ResponseField>

    <ResponseField name="contactId" type="string">

      ID of the contact representing the client in the provider's contact list.

      Use this ID to look up the client's details with the
      [Contacts API](https://dev.wix.com/docs/rest/crm/members-contacts/contacts/contacts/introduction).

    </ResponseField>

    <ResponseField name="status" type="string">

      Current status of the engagement.

      **Supported values:**

      - `NEW` — The project was created from the client's brief and no one has acted on it yet.
      - `IN_DISCUSSION` — The provider and client are discussing the engagement.
      - `IN_PROGRESS` — The provider has started work on the engagement.
      - `COMPLETED` — The provider has delivered the engagement. Final status.
      - `CANCELED_BY_CLIENT` — The client canceled the engagement. Final status.
      - `CANCELED_BY_PROVIDER` — The provider canceled the engagement. Final status.
      - `EXPIRED` — No one acted on the project before it reached its `expirationDate`. Final status.
      - `CONTACTED` — The provider has messaged the client for the first time.

    </ResponseField>

    <ResponseField name="review" type="Review">

      Client's review of the completed project, together with the provider's reply.

      Available only after the client submits a review, which they can do once the project's `status`
      is `COMPLETED`.

      <Expandable title="review properties">

        <ResponseField name="overallScore" type="integer">

          Client's rating of the engagement, where 1 is the lowest and 5 is the highest.

        </ResponseField>

        <ResponseField name="text" type="string">

          Client's written feedback on the engagement.

        </ResponseField>

        <ResponseField name="date" type="datetime">

          Date and time the review was submitted.

        </ResponseField>

        <ResponseField name="reply" type="Reply">

          Provider's reply to the review.

          Add a reply by calling Reply to Project Review. A review supports a single reply, which can't be
          changed once submitted.

          <Expandable title="reply properties">

            <ResponseField name="text" type="string">

              Provider's response to the client's review.

              Constraints: `minLength 1`.

            </ResponseField>

            <ResponseField name="date" type="datetime">

              Date and time the reply was submitted.

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="metasiteId" type="string">

      ID of the site delivered for the project.

      Serves as proof of delivery when calling Complete Project.

    </ResponseField>

    <ResponseField name="completedProjectSnapshot" type="string">

      URL of a visual snapshot of the delivered work, such as an uploaded thumbnail image or the URL of
      the delivered site.

      Serves as proof of delivery when calling Complete Project.

    </ResponseField>

    <ResponseField name="statusTimeline" type="StatusTimelineItem[]">

      NOT marked `readOnly`: the back-office console maintains this list itself and passes
      `statusTimeline` in the update mask, and a readOnly field in a mask is rejected outright.
      Remove this exemption once ProjectsBO.UpdateProject appends the timeline server-side and
      the BO client stops sending it.

      <Expandable title="statusTimeline properties">

        <ResponseField name="status" type="string">

          Status the project held.

          **Supported values:**

          - `NEW` — The project was created from the client's brief and no one has acted on it yet.
          - `IN_DISCUSSION` — The provider and client are discussing the engagement.
          - `IN_PROGRESS` — The provider has started work on the engagement.
          - `COMPLETED` — The provider has delivered the engagement. Final status.
          - `CANCELED_BY_CLIENT` — The client canceled the engagement. Final status.
          - `CANCELED_BY_PROVIDER` — The provider canceled the engagement. Final status.
          - `EXPIRED` — No one acted on the project before it reached its `expirationDate`. Final status.
          - `CONTACTED` — The provider has messaged the client for the first time.

        </ResponseField>

        <ResponseField name="date" type="datetime">

          Date and time the project held this status.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="budget" type="number">

      Agreed budget for the engagement.

      To set this value, specify `budget` when calling Complete Project.

    </ResponseField>

    <ResponseField name="cancellationInfo" type="CancellationInfo">

      Reason the project was canceled, with any additional details.

      Returned only when `status` is `CANCELED_BY_PROVIDER` or `CANCELED_BY_CLIENT`.

      <Expandable title="cancellationInfo properties">

        <ResponseField name="additionalInfo" type="string">

          Additional details about why the project was canceled.

        </ResponseField>

        <ResponseField name="reason" type="string">

          Reason the project was canceled.

          **Supported values:**

          - `OTHER` — A reason not covered by the other values.
          - `CLIENT_NOT_RESPONDING` — The client stopped responding.
          - `BUDGET_IS_TOO_LOW` — The client's budget was too low for the work.
          - `DUPLICATE_REQUEST` — The request duplicates another project.
          - `REPORT_AS_SPAM` — The request was reported as spam.
          - `DOESNT_MATCH_MY_SKILLS` — The work doesn't match the provider's skills.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="expirationDate" type="datetime">

      Date and time the project expires if no one acts on it.

      A project that's still in `NEW` status at this time moves to `EXPIRED` automatically. Once the
      project leaves `NEW` status, it no longer expires.

      **Read-only.**

    </ResponseField>

    <ResponseField name="source" type="string">

      How the engagement originated.

      **Supported values:**

      - `MATCHING` — The engagement originated from the marketplace matching flow. Also returned when the source is unknown.
      - `EXPLORE` — The client found the provider in the Wix Marketplace and contacted them directly.
      - `AI_ASSISTANT` — The engagement originated from an AI assistant conversation.

    </ResponseField>

    <ResponseField name="briefDescription" type="string">

      Client's request, copied from the brief the project was created from.

      Read this field to see what the client asked for without retrieving the brief itself.

      **Read-only.**

    </ResponseField>
