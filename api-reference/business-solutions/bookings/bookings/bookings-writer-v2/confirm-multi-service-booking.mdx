    Updates the status for all single-service bookings in a multi-service booking to `CONFIRMED`.

    Call this method for multi-service bookings requiring manual business approval.

    ### Status requirements

    - __Original status__: All single-service bookings must have `PENDING`, `CREATED`, or `WAITING_LIST` status.
    - __Target status__: All bookings move to `CONFIRMED` together (all-or-nothing operation).

    ### Checkout restrictions

    Only call this method if the customer paid via a custom checkout. For Wix eCommerce checkouts,
    Wix Bookings automatically manages the bookings' statuses based on payment processing.

    ### Additional updates

    - __Payment status__: Updates if you specify a new `confirmBookingsInfo.paymentStatus`.
    - __Customer notifications__: Send messages using `participantNotification`.
    - __Revision control__: Requires current revision numbers for all single-service bookings.

    See [Confirm Booking](https://dev.wix.com/docs/rest/business-solutions/bookings/bookings/bookings-writer-v2/confirm-booking) for more details about confirming single-service bookings.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>


    <ParamField body="confirmBookingsInfo" type="BookingInfo[]">

      Information about the single-service bookings to confirm.

      <Expandable title="confirmBookingsInfo properties">

        <ParamField body="bookingId" type="string">

          ID of the single-service booking.

        </ParamField>

        <ParamField body="revision" type="integer">

          Revision number, which increments by 1 each time the booking is updated.
          To prevent conflicting changes, the current revision must be specified when managing the booking.

        </ParamField>

        <ParamField body="paymentStatus" type="string">

          Payment status to set for the single-service booking.

          **Supported values:**

          - `UNDEFINED` — Undefined payment status.
          - `NOT_PAID` — The booking isn't paid.
          - `PAID` — The booking is fully paid.
          - `PARTIALLY_PAID` — The booking is partially paid.
          - `REFUNDED` — The booking is refunded.
          - `EXEMPT` — The booking is free of charge.
          - `FAILED` — The most recent subscription payment for this booking failed. If the payment is later recovered, the status changes back to `PAID`. Returned only for course bookings with subscription pricing.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="participantNotification" type="ParticipantNotification">

      Information about whether to notify the customer and the message to send.

          Whether to send a message about the changes to the customer.

          Default: `false`

        </ParamField>

        <ParamField body="message" type="string">

          Custom message to send to the participants about the changes to the booking.

        </ParamField>

        <ParamField body="metadata" type="object">

          Information about the delivery channels used to send the notification.
          For example, `{"channels": "SMS" }`, `{"channels": "EMAIL" }`, or `{"channels": "EMAIL, SMS" }`.

          Constraints: `format map`.

          <Expandable title="metadata properties">

            <ParamField body="key" type="string" />

            <ParamField body="value" type="string" />

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="sendSmsReminder" type="boolean">

      Whether to send an SMS reminder to the customer 24 hours before the session starts.
      Wix Bookings takes the phone number from `contactDetails.phone`.

      Default: `true`

    </ParamField>

    <ParamField body="doubleBooked" type="boolean">

      Whether this booking has a conflict with at least 1 other confirmed booking.

    </ParamField>

    <ParamField body="returnFullEntity" type="boolean">

      Whether to return the confirmed single-service bookings.

    </ParamField>

    <ParamField body="flowControlSettings" type="ConfirmBookingFlowControlSettings">

      For example, whether Wix Bookings checks availability before confirming the booking.

      <Expandable title="flowControlSettings properties">

          Whether the availability is checked before confirming the booking.

          When specifying `false`, a booking is only updated with status `CONFIRMED`.
          Default: `false`.

        </ParamField>

      </Expandable>

    </ParamField>
