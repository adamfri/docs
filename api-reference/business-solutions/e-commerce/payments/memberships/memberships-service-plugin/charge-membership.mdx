    This method requests that a membership be charged by your app.

    ## Endpoint

    ```http
    POST /v1/charge-membership
    ```

    ## Body Params

    <ParamField body="memberId" type="string" required>

      Member ID.

      Do not retrieve this from the request context. In some cases the caller is not a member, but a user who is using the membership on behalf of a member.

      Constraints: `format GUID`.

    </ParamField>

    <ParamField body="membershipId" type="string">

      Membership ID.

      Constraints: `minLength 1`, `maxLength 200`.

    </ParamField>

    <ParamField body="idempotencyKey" type="string" required>

      Idempotency key to avoid duplicate charge.
      The value is typically `membershipId` + `orderId` + `rootCatalogItemId`.

      Constraints: `minLength 1`, `maxLength 300`.

    </ParamField>

    <ParamField body="serviceProperties" type="ServiceProperties">

      Service properties.

      When relevant, this contains information such as date and number of participants.

      <Expandable title="serviceProperties properties">

        <ParamField body="scheduledDate" type="datetime">

          Date and time the service is to be provided, in [ISO-8601](https://en.wikipedia.org/wiki/ISO_8601#Combined_date_and_time_representations) format.
          For example, the start time of a class.

        </ParamField>

        <ParamField body="numberOfParticipants" type="integer">

          The number of people participating in the service. For example, the number of people attending a class or the number of people per hotel room.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="catalogReference" type="CatalogReference" required>

      Catalog and item reference info.

      <Expandable title="catalogReference properties">

        <ParamField body="catalogItemId" type="string">

          ID of the item within the catalog it belongs to.

          Constraints: `minLength 1`, `maxLength 36`.

        </ParamField>

        <ParamField body="appId" type="string" required>

          ID of the app providing the catalog.

          You can get your app's ID from its page in the [app dashboard](https://dev.wix.com/dc3/my-apps/).

          For items from Wix catalogs, the following values always apply:
          + Wix Stores: `"215238eb-22a5-4c36-9e7b-e7c08025e04e"`
          + Wix Bookings: `"13d21c63-b5ec-5912-8397-c3a5ddb27a97"`
          + Wix Restaurants: `"9a5d83fd-8570-482e-81ab-cfa88942ee60"`

          Constraints: `minLength 1`.

        </ParamField>

        <ParamField body="options" type="object">

          Additional item details in `key:value` pairs.

          Use this optional field for more specificity with item selection. The values of the `options` field differ depending on which catalog is providing the items.

          For Wix Stores products, learn more about integrating with [Catalog V3](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/e-commerce-integration)
          or [Catalog V1](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v1/catalog/e-commerce-integration), depending on [the version the site uses](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-versioning/introduction).

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="rootCatalogItemId" type="string">

      Root catalog item ID.

      The value will usually be the same as `catalogReference.catalogItemId`.
      In cases when these are not the same, this field will return the actual ID of the item in the catalog.
      For example, for Wix bookings, the value of `catalogReference.catalogItemId` is the booking ID, but `rootCatalogItemId` is set to the service ID.

    </ParamField>

    <ParamField body="additionalData" type="object">

      Additional data about this charge.

    </ParamField>

    ## Response Object

    <ResponseField name="transactionId" type="string">

      The transaction ID for this charge.

      Use this ID to void the charge.

      Constraints: `minLength 1`, `maxLength 100`.

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `400` | `INVALID_ARGUMENT` | `MEMBERSHIP_DOES_NOT_APPLY_TO_ITEM` | The membership was found, but does not apply for the provided item |
    | `428` | `FAILED_PRECONDITION` | `MEMBERSHIP_CANNOT_BE_CHARGED` | The membership was found, applied to the provided item but cannot be charged. For example because a limited membership doesn't have enough credits |
    | `409` | `ALREADY_EXISTS` | `MEMBERSHIP_ALREADY_CHARGED` | This charge was already done, per the idempotency key of membershipId + orderId + rootCatalogItemId |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
