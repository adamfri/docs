    <div className="wix-ref">

    Creates an index for a data collection.

    The index can't be used immediately, as the process of generating the index takes time.
    You can check whether an index is ready by calling List Indexes.

    Note that when an index fails to create, the failed index still occupies a slot.
    To remove the failed index and free up the slot for a new index, call Drop Index.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.DC-DATA.INDEXES-MANAGE">Manage Data Indexes</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/data/v2/indexes
    ```

    ## Body Params

    <ParamField body="index" type="Index" required>

      Details of the index to be created.

      See the [Index Object](/api-reference/business-solutions/cms/collection-management/indexes/index-object) for this object's fields.

    </ParamField>

    <ParamField body="dataCollectionId" type="string" required>

      ID of the data collection for which to generate the index.

      Constraints: `maxLength 256`.

    </ParamField>

    ## Response Object

    <ResponseField name="index" type="Index">

      Details of the index being generated.

      See the [Index Object](/api-reference/business-solutions/cms/collection-management/indexes/index-object) for this object's fields.

    </ResponseField>

    ## Method Parameters

    <ParamField body="dataCollectionId" type="string" required>

      ID of the data collection for which to generate the index.

      Constraints: `maxLength 256`.

    </ParamField>

    <ParamField body="index" type="CreateIndex" required>

      Details of the index to be created.

      <Expandable title="index properties">

        <ParamField body="_id" type="string">

          ID of the index.

          **Read-only.** Constraints: `format GUID`.

        </ParamField>

        <ParamField body="name" type="string" required>

          Name of the index.

          Constraints: `minLength 1`, `maxLength 128`.

        </ParamField>

        <ParamField body="fields" type="Field[]" required>

          Fields for which the index is defined.

          Max: 3 fields (for a unique index: 1 field)

          Constraints: `minItems 1`, `maxItems 3`.

          <Expandable title="fields properties">

            <ParamField body="path" type="string" required>

              Path of the field to index. For example: `title` or `options.price`.

              Constraints: `minLength 1`, `maxLength 128`.

            </ParamField>

            <ParamField body="order" type="string">

              Sort order for the index. Base on how the data is regularly queried.

              Default: `ASC`

              **Supported values:**

              - `ASC`
              - `DESC`

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="status" type="string">

          Current status of the index.

          **Read-only.**

          **Supported values:**

          - `BUILDING` — Index creation is in progress.
          - `ACTIVE` — Index has been successfully created and can be used in queries.
          - `DROPPING` — Index is in the process of being dropped.
          - `DROPPED` — Index has been dropped successfully.
          - `FAILED` — Index creation has failed.
          - `INVALID` — Index contains incorrectly indexed data.

        </ParamField>

        <ParamField body="failure" type="Failure">

          Contains details about the reasons for failure when `status` is `FAILED`.

          **Read-only.**

          <Expandable title="failure properties">

            <ParamField body="code" type="string">

              Error code.
              - `WDE0112`: Unknown error while building collection index.
              - `WDE0113`: Duplicate key error while building collection index.
              - `WDE0114`: Document too large while building collection index.

              Constraints: `maxLength 7`.

            </ParamField>

            <ParamField body="description" type="string">

              Description of the failure.

              Constraints: `maxLength 1024`.

            </ParamField>

            <ParamField body="itemId" type="string">

              ID of the data item that caused the failure.
              For example, if `unique` is `true`, the ID of an item containing a duplicate value.

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="unique" type="boolean">

          Whether the index enforces uniqueness of values in the field for which it's defined.
          If `true`, the index can have only 1 field.

          Default: `false`

        </ParamField>

        <ParamField body="caseInsensitive" type="boolean">

          Whether the index ignores case.

          Default: `false`

        </ParamField>

        <ParamField body="source" type="string">

          Source of the index. See index sources in [Index Types](https://dev.wix.com/docs/api-reference/business-solutions/cms/indexes/index-types#index-sources).

          Default: `USER`

          **Supported values:**

          - `SYSTEM` — Automatically created by Wix for all collections.

          System indexes are created for essential attributes, such as ID and creation date.
          You can't delete them and they don't count towards the index limit.
          - `USER` — Created by a Wix user via the API or in the dashboard.
          - `AUTO` — Created automatically by Wix based on a Wix user's queries.

          For large collections, Wix identifies slow-running queries and creates indexes automatically to improve performance.
          These indexes don't count towards the index limit. They're created dynamically, and may be deleted if they no longer fit
          the system's parameters. To keep an automatic index permanently, manually create an identical `USER` index.

        </ParamField>

      </Expandable>

    </ParamField>
