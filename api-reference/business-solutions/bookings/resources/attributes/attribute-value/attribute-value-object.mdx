---
title: "Attribute Value Object"
description: "An attribute value stores the value of an attribute definition for a specific entity."
icon: "cube"
---

An attribute value stores the value of an attribute definition for a specific entity.
Each attribute value references its definition and the entity it belongs to.

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Attribute value ID.

      **Read-only.** Constraints: `format GUID`.

    </ResponseField>

    <ResponseField name="revision" type="integer">

      Revision number, which increments by 1 each time the attribute value is updated.

      **Read-only.**

    </ResponseField>

    <ResponseField name="createdDate" type="datetime">

      Date and time the attribute value was created.

      **Read-only.**

    </ResponseField>

    <ResponseField name="updatedDate" type="datetime">

      Date and time the attribute value was last updated.

      **Read-only.**

    </ResponseField>

    <ResponseField name="attributeDefinitionId" type="string">

      ID of the attribute definition this value belongs to.

      **Read-only.** Constraints: `format GUID`.

    </ResponseField>

    <ResponseField name="entityId" type="string">

      ID of the entity this value belongs to. An entity is any resource your application owns
      (in the current Rentals integration, a Bookings resource); this API does not validate it.
      Use the same ID passed to `BulkUpsertAttributeValues` and `ListEntityAttributes`.

      **Read-only.** Constraints: `format GUID`.

    </ResponseField>

    <ResponseField name="valueType" type="string">

      Value type of this attribute. Matches the related attribute definition's value_type.
      Set on create and never changes.

      **Read-only.**

      **Supported values:**

      - `STRING` — String attribute: single-select from a predefined list of allowed string values.
      - `NUMBER` — Integer number attribute with a required min/max range.
      - `BOOL` — Boolean attribute (true/false).

    </ResponseField>

    <ResponseField name="extendedFields" type="ExtendedFields">

      Custom field data for the attribute value.
      [Extended fields](https://dev.wix.com/docs/rest/articles/getting-started/extended-fields) must be configured in the app dashboard before they can be accessed with API calls.

      <Expandable title="extendedFields properties">

        <ResponseField name="namespaces" type="object">

          Extended field data. Each key corresponds to the namespace of the app that created the extended fields.
          The value of each key is structured according to the schema defined when the extended fields were configured.

          You can only access fields for which you have the appropriate permissions.

          Learn more about [extended fields](https://dev.wix.com/docs/rest/articles/getting-started/extended-fields).

          Constraints: `format map`.

          <Expandable title="namespaces properties">

            <ResponseField name="key" type="string" />

            <ResponseField name="value" type="object" />

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Example

    <CodeGroup>

      ```json Object
      {
        "id": "b2c1a7f3-9d8e-4b5a-83f2-12d8e0a4c6c1",
        "revision": "1",
        "createdDate": "2026-05-15T09:05:00.000Z",
        "updatedDate": "2026-05-15T09:05:00.000Z",
        "attributeDefinitionId": "0a1f4a06-8d52-4a3a-9a3b-7f1f8b9c2c44",
        "groupId": "8a3c2e10-6c4d-4d8e-95b2-c1c7e9d1f3a1",
        "entityId": "5a9b3e88-1f6c-4f3b-9c7e-08e2f3b5a1b2",
        "valueType": "NUMBER",
        "numberData": 4
      }
      ```

    </CodeGroup>
