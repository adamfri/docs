---
title: "Staff Member Object"
description: "A Staff Member represents a person with predefined responsibilities for operating events."
icon: "cube"
---

A Staff Member represents a person with predefined responsibilities for operating events.

You can set each staff member's permissions and assign them to some or all events on a site.

Upon creation, Wix automatically generates a login link for the staff member to the Check-in app, where they can perform their roles without interacting with the site itself. Learn more about [Check-in](https://support.wix.com/en/article/check-in-by-wix-an-overview).

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Staff member ID.

      **Read-only.**

    </ResponseField>

    <ResponseField name="revision" type="integer">

      Revision number, which increments by 1 each time the staff member is updated. To prevent conflicting changes, the existing `revision` must be used when updating a staff member.

      **Read-only.**

    </ResponseField>

    <ResponseField name="createdDate" type="datetime">

      Date and time the staff member was created.

      **Read-only.**

    </ResponseField>

    <ResponseField name="updatedDate" type="datetime">

      Date and time the staff member was updated.

      **Read-only.**

    </ResponseField>

    <ResponseField name="name" type="string">

      Staff member name.

    </ResponseField>

    <ResponseField name="status" type="string">

      Staff member status. To change the status, call Update Staff Member.

      **Supported values:**

      - `PENDING` — The staff member hasn't logged in yet.
      - `HAS_ACCESS` — The staff member is logged in and has access to an event.
      - `ACCESS_PAUSED` — The access to an event is paused for the staff member.

    </ResponseField>

    <ResponseField name="extendedFields" type="ExtendedFields">

      Data extensions.

      <Expandable title="extendedFields properties">

        <ResponseField name="namespaces" type="object">

          Extended field data. Each key corresponds to the namespace of the app that created the extended fields.
          The value of each key is structured according to the schema defined when the extended fields were configured.

          You can only access fields for which you have the appropriate permissions.

          Learn more about [extended fields](https://dev.wix.com/docs/rest/articles/getting-started/extended-fields).

          Constraints: `format map`.

          <Expandable title="namespaces properties">

            <ResponseField name="key" type="string" />

            <ResponseField name="value" type="object" />

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="permissions" type="string[]">

      Staff member permissions.

      Constraints: `maxItems 4`.

      **Supported values:**

      - `CHECK_IN_GUESTS` — The staff member can view the guest list, check in guests, and scan tickets.
      - `SELL_TICKETS` — The staff member can sell tickets.
      - `ADD_GUESTS` — The staff member can add guests to the event manually and mark their payment status.
      - `READ_ANALYTICS` — The staff member can track tickets sales, site visits, and trends.
      - `READ_GUEST_FORM` — The staff member can see the guest's form answers.

    </ResponseField>

    <ResponseField name="loginLink" type="string">

      Login link generated for the staff member. This link opens up the [Check-in](https://support.wix.com/en/article/check-in-by-wix-an-overview) app.

      **Read-only.**

    </ResponseField>
