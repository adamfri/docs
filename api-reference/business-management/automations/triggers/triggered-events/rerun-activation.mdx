    Reruns a previous activation, reusing its original payload and external entity ID.

    Use this to retry an activation that failed, after you've resolved the underlying issue. A rerun creates a new activation. You can find the original `activationId` in the automation's run log on the automations page.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.CRM.SETUP-AUTOMATIONS">Set Up Automations</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/automations/esbConfigResolver/v1/events/rerun-activation
    ```

    ## Body Params

    <ParamField body="activationId" type="string" required>

      ID of the activation to rerun. Its original payload and external entity ID are reused.

      Constraints: `format GUID`.

    </ParamField>

    <ParamField body="options" type="RunOptions">

      Options that control how the activation is rerun.

      <Expandable title="options properties">

        <ParamField body="skipDelays" type="boolean">

          Whether to skip the automation's delay actions so it runs immediately.

        </ParamField>

      </Expandable>

    </ParamField>

    ## Response Object

    <ResponseField name="activationId" type="string">

      ID of the new activation created by the rerun.

    </ResponseField>

    ## Errors

    <Note>

      This method doesn't return any custom errors, but may return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
