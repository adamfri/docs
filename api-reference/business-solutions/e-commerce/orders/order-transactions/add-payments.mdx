    <div className="wix-ref">

    Adds up to 50 payment records to an order.

    <Note>

    + This does **NOT** perform the actual charging - the order is only updated with records of the payments.
    + The order's `paymentStatus` is recalculated asynchronously after the call. Reading the order immediately afterward may still show the previous payment status.
    + If any payment's external transaction ID already exists on the order, the entire call fails and no payments are added.

    </Note>

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.DC-STORES.MANAGE-ORDERS">Manage Orders</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/ecom/v1/payments/orders/{orderId}/add-payment
    ```

    ## Path Params

    <ParamField path="orderId" type="string" required>

      Order ID.

    </ParamField>

    ## Body Params

    <ParamField body="payments" type="Payment[]" required>

      Payments to be added to order.

      Constraints: `minItems 1`, `maxItems 50`.

      <Expandable title="payments properties">

        <ParamField body="id" type="string">

          Payment ID.

          **Read-only.**

        </ParamField>

        <ParamField body="createdDate" type="datetime">

          Date and time the payment was created in [ISO-8601](https://en.wikipedia.org/wiki/ISO_8601#Combined_date_and_time_representations) format. Defaults to current time when not provided.

        </ParamField>

        <ParamField body="updatedDate" type="datetime">

          Date and time the payment was last updated in [ISO-8601](https://en.wikipedia.org/wiki/ISO_8601#Combined_date_and_time_representations) format.

          **Read-only.**

        </ParamField>

        <ParamField body="amount" type="Price" required>

          Payment amount.

          <Expandable title="amount properties">

            <ParamField body="amount" type="string">

              Amount.

              Constraints: `>= 0`, `<= 1000000000000000`.

            </ParamField>

            <ParamField body="formattedAmount" type="string">

              Amount formatted with currency symbol.

              **Read-only.**

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="refundDisabled" type="boolean">

          Whether refunds for this payment are disabled.
          + `true`: This payment is not refundable.
          + `false`: This payment may be refunded. However, this ultimately depends on the payment provider.

        </ParamField>

        <ParamField body="cashRounding" type="CashRoundingDetails">

          Details about cash rounding applied to this payment, when relevant.

          **Developer Preview.**

          <Expandable title="cashRounding properties">

            <ParamField body="unroundedAmount" type="Price">

              Payment amount before cash rounding was applied.
              When provided, balance and status calculations use this value instead of `amount`
              to prevent false overpayment or underpayment due to rounding.

              **Developer Preview.**

              _Nested structure omitted for brevity — see the `Price` object._

            </ParamField>

            <ParamField body="roundingAdjustment" type="CashRounding">

              The difference between 'amount' and 'unroundedAmount' (amount minus unroundedAmount).
              A positive value indicates the price was rounded up; a negative value indicates a round-down.

              **Read-only.** **Developer Preview.**

              _Nested structure omitted for brevity — see the `CashRounding` object._

            </ParamField>

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    ## Response Object

    <ResponseField name="orderTransactions" type="OrderTransactions">

      Order ID and its associated transactions.

      See the [Order Transactions Object](/api-reference/business-solutions/e-commerce/orders/order-transactions/order-transactions-object) for this object's fields.

    </ResponseField>

    <ResponseField name="paymentsIds" type="string[]">

      IDs of added order payments.

    </ResponseField>

    ## Errors

    <Note>

      This method doesn't return any custom errors, but may return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>

    This method triggers the following events:

    | Order Transactions Details Updated | `wix.ecom.v1.order_transactions_details_updated` | Triggered when a payment or refund is added to an order, or when an existing payment is updated. Contains the ID of the updated order and details of its associated transactions, as well as IDs of the updated payments and refunds. |
