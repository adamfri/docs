    Retrieves an account's current AI credit balance.

    The balance includes recurring (periodic) credits, one-time top-up credits, and a per-source
    breakdown of the same credits. Use it to check an account's available credits before running an
    AI action, or to display the balance to an account.

    The data returned depends on the caller's access. With account-level access, the response covers
    all of the account's credits. With site-level access, the response is scoped to the credits and
    subscription of the site in context. When the caller has both, the account-level balance is returned.

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="appmarket:credittransactions:v1:credit_transaction:get_account_credit_balance">appmarket:credittransactions:v1:credit_transaction:get_account_credit_balance</span>
    <span className="wix-scope" title="appmarket:credittransactions:v1:credit_transaction:get_site_credit_balance">appmarket:credittransactions:v1:credit_transaction:get_site_credit_balance</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    ## Endpoint

    ```http
    POST https://www.wixapis.com/appmarket/credittransactions/v1/credit-transactions/balance
    ```

    ## Response Object

    <ResponseField name="periodicCredits" type="Periodic">

      An account's recurring (periodic) credits, aggregated across all sources.

      Recurring credits replenish each period, such as monthly.

      Returned only when the account has recurring credits.

      <Expandable title="periodicCredits properties">

        <ResponseField name="balance" type="integer">

          Remaining recurring credits currently available.

          Decreases as credits are consumed and replenishes each period.

          Constraints: `min 0`.

        </ResponseField>

        <ResponseField name="cap" type="integer">

          Maximum recurring credits available per period.

          Constraints: `min 0`.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="topUpCredits" type="TopUp">

      An account's one-time top-up credits, aggregated across all purchases.

      Top-up credits supplement recurring credits and don't reset.

      Returned only when the account has top-up credits.

      <Expandable title="topUpCredits properties">

        <ResponseField name="balance" type="integer">

          Remaining one-time top-up credits currently available.

          Constraints: `min 0`.

        </ResponseField>

        <ResponseField name="cap" type="integer">

          Maximum one-time top-up credits available.

          Constraints: `min 0`.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="creditBalanceBreakdown" type="CreditBalance[]">

      A per-source breakdown of the account's credit balances.

      Each entry covers a distinct credit allocation and its usage rules, so you can track credits from
      different sources separately. This is a detailed view of the same credits aggregated in
      `periodicCredits` and `topUpCredits`, not additional credits.

      Constraints: `maxItems 1000`.

      <Expandable title="creditBalanceBreakdown properties">

        <ResponseField name="subscriptionId" type="string">

          ID of the subscription this credit allocation belongs to.

          Empty for credits that aren't tied to a subscription.

        </ResponseField>

        <ResponseField name="usageRules" type="UsageRule[]">

          Rules that define how the credits in this allocation can be consumed.

          Multiple rules can apply together, such as a daily limit within a monthly allocation.

          Constraints: `maxItems 10`.

          <Expandable title="usageRules properties">

            <ResponseField name="period" type="string">

              How often the credits under this rule replenish, such as daily or monthly.

              Some credits have no period, meaning they're one-time and don't reset.

              **Supported values:**

              - `NO_PERIOD`
              - `MILLISECOND`
              - `SECOND`
              - `MINUTE`
              - `HOUR`
              - `DAY`
              - `WEEK`
              - `MONTH`
              - `YEAR`

            </ResponseField>

            <ResponseField name="balance" type="integer">

              Remaining credits available under this rule.

            </ResponseField>

            <ResponseField name="cap" type="integer">

              Maximum credits allowed under this rule per period.

            </ResponseField>

            <ResponseField name="resetDate" type="datetime">

              Date and time when this rule's balance resets to `cap`.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="planTierId" type="string">

          Premium product-family id (the plan tier) backing this credit allocation.

          Empty when no active premium asset matches the subscription.

          Constraints: `format GUID`.

        </ResponseField>

        <ResponseField name="autoRenew" type="boolean">

          Whether the backing premium subscription renews automatically.

          `false` when no active premium asset matches the subscription.

        </ResponseField>

        <ResponseField name="planName" type="string">

          Display name of the premium plan (product name) backing this credit allocation.

          Empty when no active premium asset matches the subscription.

          Constraints: `maxLength 200`.

        </ResponseField>

      </Expandable>

    </ResponseField>
