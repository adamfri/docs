    <div className="wix-ref">

    Lists published comments and replies from a specified resource, such as a blog post.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.DC_COMMENTS.READ.COMMENTS">Read Comments</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    GET https://www.wixapis.com/comments/v1/comments/list-by-resource
    ```

    ## Query Params

    <ParamField query="appId" type="string" required>

      ID of the app from which the comments are listed.

      Constraints: `format GUID`.

    </ParamField>

    <ParamField query="contextId" type="string" required>

      ID of the specific context the comment is in response to.

      Within some Wix apps, the `contextId` will be the same as the `resourceId`. For example in Wix Forum, the `forumPostId` is used as both the `contextId` and the `resourceId`.

      Constraints: `maxLength 128`.

    </ParamField>

    <ParamField query="contextType" type="string">

      Reserved for internal use.

      Constraints: `maxLength 128`.

    </ParamField>

    <ParamField query="resourceId" type="string" required>

      ID of the specific resource that the comment is in response to.

      Within some Wix apps, the `resourceId` will be the same as the `contextId`. For example in Wix Forum, the `forumPostId` is used as both the `resourceId` and the `contextId`.

      Constraints: `maxLength 128`.

    </ParamField>

    <ParamField query="commentSort" type="CommentSort">

      Comment sort. Is ignored if `cursorPaging.cursor` is defined.

      <Expandable title="commentSort properties">

        <ParamField query="order" type="string">

          Sort order.

          **Supported values:**

          - `UNKNOWN_ORDER` — Unknown order.
          - `OLDEST_FIRST` — Oldest comments appear at the top of the list.
          - `NEWEST_FIRST` — Newest comments appear at the top of the list.
          - `REACTION_COUNT` — Comments with the highest reaction count appear at the top of the list.
          - `NET_VOTE_COUNT` — Comments with the highest vote count appear at the top of the list.
          - `RATING` — Comments with the highest rating appear at the top of the list.
          - `NET_VOTE_COUNT_ASC` — Comments with the lowest vote count appear at the top of the list.
          - `RATING_ASC` — Comments with the lowest rating appear at the top of the list.

        </ParamField>

        <ParamField query="keepMarkedInOriginalOrder" type="boolean">

          If set to `true`, marked comments appear in the original order, and not at the top of the list.

          Default: `false`. This means that marked comments are prioritized and listed first.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField query="replySort" type="ReplySort">

      Reply sort. Is ignored if `cursorPaging.cursor` is defined.

      <Expandable title="replySort properties">

        <ParamField query="order" type="string">

          Sort order.

          **Supported values:**

          - `UNKNOWN_ORDER` — Unknown order.
          - `OLDEST_FIRST` — Oldest comments appear at the top of the list.
          - `NEWEST_FIRST` — Newest comments appear at the top of the list.
          - `REACTION_COUNT` — Comments with the highest reaction count appear at the top of the list.

        </ParamField>

        <ParamField query="keepMarkedInOriginalOrder" type="boolean">

          Whether the marked comments are listed in the original order.

          If set to `true`, marked comments appear in the original order, and not at the top of the list.

          Default: `false`. In this case marked comments are prioritized and listed first.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField query="cursorPaging" type="ListCommentsByResourceCursorPaging">

      Cursor paging.

      <Expandable title="cursorPaging properties">

        <ParamField query="cursor" type="string">

          Pointer to the next or previous page in the list of results.

        </ParamField>

        <ParamField query="limit" type="integer">

          Number of items to return.

        </ParamField>

        <ParamField query="repliesLimit" type="integer">

          Maximum number of replies in a response. Only applicable to parent comments.

        </ParamField>

      </Expandable>

    </ParamField>

    ## Response Object

    <ResponseField name="comments" type="Comment[]">

      Listed comments.

      See the [Comment Object](/api-reference/crm/community/feedback-moderation/comments/comments/comment-object) for this object's fields.

    </ResponseField>

    <ResponseField name="pagingMetadata" type="CursorPagingMetadata">

      Paging metadata.

      <Expandable title="pagingMetadata properties">

        <ResponseField name="count" type="integer">

          Number of items returned in current page.

        </ResponseField>

        <ResponseField name="cursors" type="Cursors">

          Cursor strings that point to the next page, previous page, or both.

          <Expandable title="cursors properties">

            <ResponseField name="next" type="string">

              Cursor string pointing to the next page in the list of results.

            </ResponseField>

            <ResponseField name="prev" type="string">

              Cursor pointing to the previous page in the list of results.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="hasNext" type="boolean">

          Whether there are more pages to retrieve following the current page.

          + `true`: Another page of results can be retrieved.
          + `false`: This is the last page.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="commentReplies" type="object">

      Listed comment replies.

      Constraints: `format map`.

      <Expandable title="commentReplies properties">

        <ResponseField name="key" type="string" />

        <ResponseField name="value" type="RepliesListResponse">

          <Expandable title="value properties">

            <ResponseField name="replies" type="Comment[]">

              Listed comment replies.

              See the [Comment Object](/api-reference/crm/community/feedback-moderation/comments/comments/comment-object) for this object's fields.

            </ResponseField>

            <ResponseField name="pagingMetadata" type="CursorPagingMetadata">

              Paging metadata.

              _Nested structure omitted for brevity — see the `CursorPagingMetadata` object._

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Errors

    <Note>

      This method doesn't return any custom errors, but may return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
