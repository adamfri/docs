    Updates the booking status to `CONFIRMED` without checking whether the relevant slot or schedule is still available.

    ### eCommerce checkout restriction

    Call this method only when using a custom checkout page. Don't
    call it when using a [Wix eCommerce checkout](https://dev.wix.com/docs/rest/business-solutions/e-commerce/checkout/introduction).
    In such cases, Wix automatically updates the booking status based on
    the `paymentStatus` of the corresponding [Wix eCommerce order](https://dev.wix.com/docs/rest/business-solutions/e-commerce/orders/introduction).

    ### When to call Confirm Booking

    When using a custom checkout flow for free bookings, call this method to confirm bookings even when a double booking conflict exists.
    The alternative [Confirm or Decline Booking](https://dev.wix.com/docs/rest/business-solutions/bookings/bookings/bookings-writer-v2/confirm-or-decline-booking) method doesn't support confirming double-booked free bookings in this scenario.

    ### When to call Confirm Or Decline Booking instead

    Confirm Booking doesn't check whether a slot or schedule is still available.
    For these checks, call [Confirm or Decline Booking](https://dev.wix.com/docs/rest/business-solutions/bookings/bookings/bookings-writer-v2/confirm-or-decline-booking) instead.

    ### Original status validation

    You can only confirm bookings with a status of `PENDING`, `CREATED`, or
    `WAITING_LIST`.

    ### Double bookings

    Confirm Booking doesn't check whether a slot or schedule is still available.
    You can specify

    ```json
    {
    "flowControlSettings": {
    "checkAvailabilityValidation": true
    },
    "doubleBooked": true
    }
    ```
    to forcefully set the booking's `doubleBooked` flag to `true`, regardless of
    a potential double booking conflict. You must call with `Manage Bookings`
    permissions to do so. For the default flow control settings
    `{"checkAvailabilityValidation": false}`, the specified `doubleBooked` value
    is ignored.

    ### Payment status

    Also updates the booking's `paymentStatus`, if you specify a new payment
    status.

    ### Notify customers

    You can specify a `participantNotification.message` for the customer. To send
    the message, you must also specify `participantNotification.notifyParticipants`
    as `true`.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    ## Endpoint

    ```http
    POST https://www.wixapis.com/bookings/v2/bookings/{bookingId}/confirm
    ```

    ## Path Params

    <ParamField path="bookingId" type="string" required>

      ID of the booking to confirm.

    </ParamField>

    ## Body Params

    <ParamField body="revision" type="integer" required>

      Revision number, which increments by 1 each time the booking is updated.
      To prevent conflicting changes, the current revision must be passed when
      updating the booking.

    </ParamField>

    <ParamField body="participantNotification" type="ParticipantNotification">

      Information about whether to notify the customer about the confirmation and
      the message to send.

      <Expandable title="participantNotification properties">

        <ParamField body="notifyParticipants" type="boolean">

          Whether to send a message about the changes to the customer.

          Default: `false`

        </ParamField>

        <ParamField body="message" type="string">

          Custom message to send to the participants about the changes to the booking.

        </ParamField>

        <ParamField body="metadata" type="object">

          Information about the delivery channels used to send the notification.
          For example, `{"channels": "SMS" }`, `{"channels": "EMAIL" }`, or `{"channels": "EMAIL, SMS" }`.

          Constraints: `format map`.

          <Expandable title="metadata properties">

            <ParamField body="key" type="string" />

            <ParamField body="value" type="string" />

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="sendSmsReminder" type="boolean">

      Whether to send an SMS reminder to the customer 24 hours before the
      session starts. The phone number is taken from `contactDetails.phone`.

    </ParamField>

    <ParamField body="paymentStatus" type="string">

      Payment status to set for the booking.

      **Supported values:**

      - `UNDEFINED` — Undefined payment status.
      - `NOT_PAID` — The booking isn't paid.
      - `PAID` — The booking is fully paid.
      - `PARTIALLY_PAID` — The booking is partially paid.
      - `REFUNDED` — The booking is refunded.
      - `EXEMPT` — The booking is free of charge.
      - `FAILED` — The most recent subscription payment for this booking failed. If the payment is later recovered, the status changes back to `PAID`. Returned only for course bookings with subscription pricing.

    </ParamField>

    <ParamField body="doubleBooked" type="boolean">

      Whether this booking has a conflict with at least 1 other confirmed booking.

    </ParamField>

    <ParamField body="flowControlSettings" type="ConfirmBookingFlowControlSettings">

      Whether to ignore specific standard procedures of the Wix Bookings flow.
      For example, whether to check availability when confirming a booking.

      <Expandable title="flowControlSettings properties">

        <ParamField body="checkAvailabilityValidation" type="boolean">

          Whether the availability is checked before confirming the booking.

          When specifying `false`, a booking is only updated with status `CONFIRMED`.
          Default: `false`.

        </ParamField>

      </Expandable>

    </ParamField>

    <ResponseField name="booking" type="Booking">

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `404` | `NOT_FOUND` | `BOOKING_NOT_FOUND` | Couldn't find the booking. |
    | `428` | `FAILED_PRECONDITION` | `FAILED_CONFIRMING_NON_PENDING_BOOKING` | Can't confirm a booking that isn't in `PENDING` status. Only pending bookings can be confirmed. |
    | `428` | `FAILED_PRECONDITION` | `INVALID_BOOKING_STATUS` | The booking status is invalid. Verify the booking status before performing this action. |
    | `428` | `FAILED_PRECONDITION` | `NO_OPEN_SPOTS` | The session or schedule is fully booked. There are no available spots remaining. |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).
