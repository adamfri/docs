---
title: "Attribute Definition Object"
description: "An attribute definition is a typed custom property (string, number, or boolean) that can be applied to entities."
icon: "cube"
---

An attribute definition is a typed custom property (string, number, or boolean) that can be
applied to entities. Each definition has a display name shown to end users, a value type,
optional type-specific configuration (such as a list of allowed string values), and a
default value.

Attribute definitions are defined once per site. To set a value for a specific entity,
call Bulk Upsert Attribute Values; to read an entity's values together with their
definitions, call List Entity Attributes.

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Attribute definition ID.

      **Read-only.** Constraints: `format GUID`.

    </ResponseField>

    <ResponseField name="revision" type="integer">

      Revision number, which increments by 1 each time the attribute definition is updated.
      To prevent conflicting changes, the current revision must be passed when updating.
      Ignored when creating an attribute definition.

      **Read-only.**

    </ResponseField>

    <ResponseField name="createdDate" type="datetime">

      Date and time the attribute definition was created.

      **Read-only.**

    </ResponseField>

    <ResponseField name="updatedDate" type="datetime">

      Date and time the attribute definition was last updated.

      **Read-only.**

    </ResponseField>

    <ResponseField name="name" type="string">

      Display name for the attribute, shown to end users (for example, `Capacity`).

      Must be unique within the site. Required when creating an attribute definition.

    </ResponseField>

    <ResponseField name="valueType" type="string">

      Value type of this attribute.
      Immutable after creation. `UpdateAttributeDefinition` rejects requests that change `value_type`.
      Required when creating an attribute definition.

      **Supported values:**

      - `STRING` — String attribute: single-select from a predefined list of allowed string values.
      - `NUMBER` — Integer number attribute with a required min/max range.
      - `BOOL` — Boolean attribute (true/false).

    </ResponseField>

    <ResponseField name="visibility" type="boolean">

      Whether this attribute is shown to end users on the public site.

      - `true`: shown in the UI and available for filtering.
      - `false`: hidden from end users. Back-office admins can still see and edit the attribute.

      Default: `true`.

    </ResponseField>

    <ResponseField name="defaultValue" type="AttributeDefaultValue">

      Default value for the attribute. When a configuration change leaves a stored
      attribute value out of range or outside the allowed values, that value is reset to this
      default (see Update Attribute Definition).

      The variant must match `valueType`. Required when creating an attribute definition.

      <Expandable title="One of the following">

        <ResponseField name="value" type="value">

          value

          <Expandable title="value properties">

            <ResponseField name="stringDefault" type="string">

              Default value for a STRING-type attribute. Must be in StringConfig.allowed_values.

              Constraints: `maxLength 40`.

            </ResponseField>

            <ResponseField name="numberDefault" type="integer">

              Default value for a NUMBER-type attribute. Must be within NumberConfig [min, max].

            </ResponseField>

            <ResponseField name="boolDefault" type="boolean">

              Default value for a BOOL-type attribute.

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="extendedFields" type="ExtendedFields">

      Custom field data for the attribute definition.
      [Extended fields](https://dev.wix.com/docs/rest/articles/getting-started/extended-fields) must be configured in the app dashboard before they can be accessed with API calls.

      <Expandable title="extendedFields properties">

        <ResponseField name="namespaces" type="object">

          Extended field data. Each key corresponds to the namespace of the app that created the extended fields.
          The value of each key is structured according to the schema defined when the extended fields were configured.

          You can only access fields for which you have the appropriate permissions.

          Learn more about [extended fields](https://dev.wix.com/docs/rest/articles/getting-started/extended-fields).

          Constraints: `format map`.

          <Expandable title="namespaces properties">

            <ResponseField name="key" type="string" />

            <ResponseField name="value" type="object" />

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="tags" type="Tags">

      Custom tags for organizing and filtering attribute definitions.
      Manage tags using `BulkUpdateAttributeDefinitionTags` or `BulkUpdateAttributeDefinitionTagsByFilter`.

      <Expandable title="tags properties">

        <ResponseField name="privateTags" type="TagList">

          Tags that require an additional permission in order to access them, normally not given to site members or visitors.

          <Expandable title="privateTags properties">

            <ResponseField name="tagIds" type="string[]">

              List of tag IDs.

              Constraints: `maxLength 5`, `maxItems 100`.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="publicTags" type="TagList">

          Tags that are exposed to anyone who has access to the labeled entity itself, including site members and visitors.

          <Expandable title="publicTags properties">

            <ResponseField name="tagIds" type="string[]">

              List of tag IDs.

              Constraints: `maxLength 5`, `maxItems 100`.

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Example

    <CodeGroup>

      ```json Object
      {
        "id": "0a1f4a06-8d52-4a3a-9a3b-7f1f8b9c2c44",
        "revision": "1",
        "createdDate": "2026-05-15T09:00:00.000Z",
        "updatedDate": "2026-05-15T09:00:00.000Z",
        "name": "Capacity",
        "valueType": "NUMBER",
        "numberConfig": {
          "min": 1,
          "max": 20
        },
        "visibility": true,
        "defaultValue": {
          "numberDefault": 2
        },
        "groupIds": [
          "8a3c2e10-6c4d-4d8e-95b2-c1c7e9d1f3a1"
        ]
      }
      ```

    </CodeGroup>
