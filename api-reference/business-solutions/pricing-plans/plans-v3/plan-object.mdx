          Constraints: `minLength 1`, `maxLength 255`.

        <ResponseField name="freeTrialDays" type="integer">

          Number of days customers can use the plan for free before the first charge. Set to `0` for no free trial.

          Constraints: `min 0`, `max 999`.

        <ResponseField name="fees" type="Fee[]">

        <ResponseField name="billingTerms" type="BillingTerms">

          Billing configuration that defines when and how often customers are charged.

          <Expandable title="billingTerms properties">

              <Expandable title="billingCycle properties">

                <ResponseField name="count" type="string">

                  Constraints: `min 1`.

              When the billing starts.

              **Supported values:**

              - `ON_PURCHASE` — Billing starts immediately after purchase.
              - `CUSTOM` — Customer can choose when billing starts.

            </ResponseField>

            <ResponseField name="endType" type="string">

              **Supported values:**

              - `UNTIL_CANCELLED` — Plan continues until customer cancels.

        <ResponseField name="categoryIds" type="string[]">

          IDs of the categories this variant belongs to. Categories group variants across plans
          (for example into a "Monthly / Yearly" selector) independently of billing cycle. Optional.

          **Developer Preview.** Constraints: `format GUID`, `maxItems 1`.

        </ResponseField>

        <ResponseField name="priceOverrides" type="PriceOverrides">

          Rules that override this pricing variant's price for purchases that meet their conditions.
          Applied during purchase. An override that matches the purchase always replaces the variant's original price,
          even when the resulting price is higher. If multiple overrides match the same purchase, the lowest resulting
          price among them wins - the original price doesn't participate in this comparison.
          The overridden price applies to every billing cycle of the resulting subscription, not only the first payment.
          Updates replace the entire list of overrides. To remove all overrides, set this field to `null` -
          an empty overrides list isn't accepted.

          **Developer Preview.**

          <Expandable title="priceOverrides properties">

            <ResponseField name="overrides" type="PriceOverride[]">

              Price override rules.

              Constraints: `minItems 1`, `maxItems 10`.

              <Expandable title="overrides properties">

                <ResponseField name="id" type="string">

                  Price override ID. Must be unique within the pricing variant.

                  Constraints: `format GUID`.

                </ResponseField>

                <ResponseField name="conditions" type="PurchaseConditions">

                  Conditions a purchase must meet for this override to apply.

                  _Nested structure omitted for brevity — see the `PurchaseConditions` object._

                </ResponseField>

                <ResponseField name="overrideType" type="string">

                  How the pricing variant's price is overridden.

                  **Supported values:**

                  - `FIXED_PRICE` — The pricing variant's price is replaced with a fixed price.
                  - `PERCENTAGE_DISCOUNT` — The pricing variant's price is reduced by a percentage.

                </ResponseField>

              </Expandable>

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="feeOverrides" type="FeeOverrides">

          Rules that override specific fees of this pricing variant for purchases that meet their conditions.
          Applied during purchase. If multiple overrides apply to the same fee, the lowest resulting fee amount wins, with a waived fee counting as `0`.
          Updates replace the entire list of overrides. To remove all overrides, set this field to `null` -
          an empty overrides list isn't accepted.

          **Developer Preview.**

          <Expandable title="feeOverrides properties">

            <ResponseField name="overrides" type="FeeOverride[]">

              Fee override rules.

              Constraints: `minItems 1`, `maxItems 10`.

              <Expandable title="overrides properties">

                <ResponseField name="id" type="string">

                  Fee override ID. Must be unique within the pricing variant.

                  Constraints: `format GUID`.

                </ResponseField>

                <ResponseField name="feeId" type="string">

                  ID of the fee on the same pricing variant that this override applies to.

                  Constraints: `format GUID`.

                </ResponseField>

                <ResponseField name="conditions" type="PurchaseConditions">

                  Conditions a purchase must meet for this override to apply.

                  _Nested structure omitted for brevity — see the `PurchaseConditions` object._

                </ResponseField>

                <ResponseField name="overrideType" type="string">

                  How the fee is overridden.

                  **Supported values:**

                  - `FIXED_AMOUNT` — The fee's amount is replaced with a fixed amount.
                  - `WAIVED` — The fee isn't applied to the purchase at all.

                </ResponseField>

              </Expandable>

            </ResponseField>

          </Expandable>

    <ResponseField name="buyable" type="boolean">

      Whether customers can currently purchase this plan. If set to `false`, customer won't be able to buy a plan themselves. In this case a Wix user has to assign the plan through the [dashboard](https://support.wix.com/en/article/pricing-plans-selling-plans-offline).

    <ResponseField name="formId" type="string">

      ID of the form associated with the plan at checkout.

    </ResponseField>

    <ResponseField name="buyerCanCancel" type="boolean">

      Whether buyers can cancel their subscription to this plan.

    </ResponseField>

    <ResponseField name="currency" type="string">

      Three-letter currency code in [ISO-4217 alphabetic](https://en.wikipedia.org/wiki/ISO_4217#Active_codes) format.
      When the site currency changes, monetary amounts stored on the plan (prices, fees, and override amounts)
      are automatically rounded to the number of decimal places supported by the new currency.

      **Read-only.** Constraints: `format CURRENCY`.

    </ResponseField>

    <ResponseField name="purchaseLimits" type="PurchaseLimit[]">

      Caps how many subscriptions buyers can have or the site can sell for this plan.
      When multiple types are present, all must pass (AND logic).
      Duplicate types are rejected by the server.

      **Developer Preview.** Constraints: `maxItems 4`.

      <Expandable title="purchaseLimits properties">

        <ResponseField name="type" type="string">

          The type of purchase limit.

          **Supported values:**

          - `PER_MEMBER_LIFETIME` — Limits the total number of subscriptions (any status) a single member can have over their lifetime.
          - `PER_MEMBER_ACTIVE` — Limits the number of ongoing (ACTIVE, PENDING, PAUSED) subscriptions a single member can have at any time.
          - `TOTAL_ACTIVE` — Limits the total number of ongoing (ACTIVE, PENDING, PAUSED) subscriptions across all members at any time.
          - `TOTAL_SOLD` — Limits the total number of subscriptions ever created (any status) across all members.

        </ResponseField>

        <ResponseField name="maxCount" type="integer">

          The maximum number of subscriptions allowed.

          Constraints: `min 1`, `max 10000`.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="startDateSettings" type="StartDateSettings">

      Settings that control when subscriptions to this plan start.
      Applied during purchase to calculate the subscription start date and validate customer-selected start dates.
      The settings apply only to pricing variants with a compatible `billing_terms.start_type`:
      `FIXED_DATE` and `DAY_OF_MONTH` apply to variants with the `ON_PURCHASE` start type,
      while `DATE_RANGE` applies to variants with the `CUSTOM` start type.

      **Developer Preview.**

      <Expandable title="startDateSettings properties">

        <ResponseField name="type" type="string">

          How the subscription start date is determined.

          **Supported values:**

          - `FIXED_DATE` — Subscription starts on a single fixed date.
          Applies only to pricing variants with the `ON_PURCHASE` start type.
          - `DAY_OF_MONTH` — Subscription starts on a specific day of each month.
          Applies only to pricing variants with the `ON_PURCHASE` start type.
          - `DATE_RANGE` — Customer selects a start date within a date range.
          Applies only to pricing variants with the `CUSTOM` start type.

        </ResponseField>

        <ResponseField name="startDateUnavailableMessage" type="string">

          Message displayed to customers when no start date is available. For example, when the fixed start date or the end of the date range has passed.
          Applicable only when `type` is `FIXED_DATE`, or `DATE_RANGE` with `date_range_options.end_date` set -
          in other configurations a start date is always available and the message is ignored.

        </ResponseField>

      </Expandable>

      <Expandable title="One of the following">

        <ResponseField name="startDateOption" type="startDateOption">

          startDateOption

          <Expandable title="startDateOption properties">

            <ResponseField name="fixedDateOptions" type="FixedDateOptions">

              Subscription starts on a single fixed date.

              <Expandable title="fixedDateOptions properties">

                <ResponseField name="startDate" type="datetime">

                  Date and time when the subscription starts.

                </ResponseField>

              </Expandable>

            </ResponseField>

            <ResponseField name="dayOfMonthOptions" type="DayOfMonthOptions">

              Subscription starts on a specific day of each month.

              <Expandable title="dayOfMonthOptions properties">

                <ResponseField name="dayOfMonth" type="integer">

                  Day of the month the subscription starts. For months with fewer days, the subscription starts on the last day of the month.
                  If the purchase happens on the configured day, the subscription starts on that same day.
                  Only determines the subscription start date - subsequent billing cycles follow the
                  pricing variant's `billing_terms.billing_cycle` from that start date.

                  Constraints: `min 1`, `max 31`.

                </ResponseField>

              </Expandable>

            </ResponseField>

            <ResponseField name="dateRangeOptions" type="DateRangeOptions">

              Customer selects a start date within a date range.

              <Expandable title="dateRangeOptions properties">

                <ResponseField name="startDate" type="datetime">

                  Date and time from which the customer can select the subscription start date.
                  The selected start date must be on or after this exact instant.

                </ResponseField>

                <ResponseField name="endDate" type="datetime">

                  Date and time until which the customer can select the subscription start date. If not set, the range is open-ended.
                  The selected start date must be before this exact instant.
                  Must be later than `start_date`.

                </ResponseField>

              </Expandable>

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>
