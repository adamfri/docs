    Updates the booking status to `CANCELED`.

    ### Appointments

    For appointments, the corresponding event is removed from the Bookings
    calendar.

    ### Class and course bookings

    For class or course bookings, the relevant participants are removed
    from the class session or the course. However, the class session or course
    remain on the business calendar.

    ### Notify customers

    You can specify a `participantNotification.message` for the customer. To send
    the message, you must also specify `participantNotification.notifyParticipants`
    as `true`.

    ### Admin overwrites

    There are small but important differences when you specify special
    `flowControlSettings`:

    - `{"ignoreCancellationPolicy": true}`: The call succeeds even if the
    service's `cancellationPolicy` doesn't allow it.
    - `{"withRefund": true}`: The customer is refunded even if the service's
    `refundPolicy` doesn't allow it.
    - `{"waiveCancellationFee": true}`: The customer doesn't have to pay
    the cancellation fee, even if the service's `cancellationPolicy` requires it.

    When using special `flowControlSettings`, ensure you have sufficient
    permissions. If you encounter failed calls due to insufficient permissions,
    consider the following options:

    - **App developers** can use a higher
    [permission](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions),
    such as `MANAGE BOOKINGS - ALL PERMISSIONS`.
    - **Site developers** can utilize
    [elevation](https://dev.wix.com/docs/develop-websites/articles/coding-with-velo/authorization/elevation).

    Granting additional permissions and using elevation permits method calls that
    would typically fail due to authorization checks. Therefore, you should use
    them intentionally and securely.

    ## Permissions

    This method requires one of the following permission scopes:

    <span className="wix-scope" title="SCOPE.DC-BOOKINGS.MANAGE-BOOKINGS">Manage Bookings</span>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`, `MEMBER`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/bookings/v2/bookings/{bookingId}/cancel
    ```

    ## Path Params

    <ParamField path="bookingId" type="string" required>

      ID of the booking to cancel.

    </ParamField>

    ## Body Params

    <ParamField body="participantNotification" type="ParticipantNotification">

      Information about whether to notify the customer about the cancellation and
      the message to send.

      <Expandable title="participantNotification properties">

        <ParamField body="notifyParticipants" type="boolean">

          Whether to send a message about the changes to the customer.

          Default: `false`

        </ParamField>

        <ParamField body="message" type="string">

          Custom message to send to the participants about the changes to the booking.

        </ParamField>

        <ParamField body="metadata" type="object">

          Information about the delivery channels used to send the notification.
          For example, `{"channels": "SMS" }`, `{"channels": "EMAIL" }`, or `{"channels": "EMAIL, SMS" }`.

          Constraints: `format map`.

          <Expandable title="metadata properties">

            <ParamField body="key" type="string" />

            <ParamField body="value" type="string" />

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="flowControlSettings" type="CancelBookingFlowControlSettings">

      Whether to ignore specific standard procedures of the Wix Bookings flow.
      For example, whether to allow a cancellation even though the service's
      policy doesn't allow it.

      <Expandable title="flowControlSettings properties">

        <ParamField body="ignoreCancellationPolicy" type="boolean">

          Whether the cancellation policy applies when canceling the booking.

          When passing `false`, you can only cancel a booking if the cancellation policy allows it.
          Default: `false`.

        </ParamField>

        <ParamField body="withRefund" type="boolean">

          Whether to issue a refund when canceling the booking.

          The refund will be issued only if the booking is refundable.
          Currently, a booking is considered refundable when it was paid by membership.
          If you specify `true`, the booking flow control settings is set to include a refund.
          If `false` is specified or the field remains empty,
          the booking flow control settings are set without refund.

          Default: `false`.

        </ParamField>

        <ParamField body="waiveCancellationFee" type="boolean">

          Whether to waive the cancellation fee when canceling the booking.

          - `true`: The customer doesn't have to pay a cancellation fee.
          - `false`: The customer must pay the cancellation fee that's defined in the service's [policy](https://dev.wix.com/docs/api-reference/business-solutions/bookings/policies/booking-policies/introduction).

          Default: `false`.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="revision" type="integer" required>

      Revision number, which increments by 1 each time the booking is updated.

      To prevent conflicting changes, the current revision must be specified when
      managing the booking.

    </ParamField>

    <ParamField body="waiveCharges" type="boolean">

      Whether to waive charges and cancel the associated [Wix eCommerce order](https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/orders/introduction).

      This field only applies to bookings paid via [Wix eCommerce checkout](https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/purchase-flow/checkout/introduction). It has no effect for bookings paid through a custom checkout.

      The booking itself is always canceled. When `true`, the associated eCommerce order is also canceled if all of the following conditions are met:

      - All line items in the order belong to Wix Bookings.
      - The order's payment status is `NOT_PAID` or `PARTIALLY_PAID`.
      - The order has a positive outstanding balance. A booking for a free service, for
      example, may carry a `NOT_PAID` status while its balance is $0, making it ineligible.
      - The booking has no fees. To check, call
      [List Booking Fees by Booking IDs](https://dev.wix.com/docs/api-reference/business-solutions/bookings/pricing/booking-fees/list-booking-fees-by-booking-ids):
      the order is eligible when the returned list is empty.
      - The order has no additional fees on the booking's line item.

      Default: `false`.

    </ParamField>

    ## Response Object

    <ResponseField name="booking" type="Booking">

      Canceled booking.

      See the [Booking Object](/api-reference/business-solutions/bookings/bookings/bookings-writer-v2/booking-object) for this object's fields.

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `404` | `NOT_FOUND` | `BOOKING_NOT_FOUND` | Couldn't find the booking. |
    | `403` | `PERMISSION_DENIED` | `BOOKING_POLICY_VIOLATION` | The booking violates the service's booking policy. Check booking window restrictions, advance notice requirements, or scheduling rules. |
    | `428` | `FAILED_PRECONDITION` | `VALIDATION_FAILURE` | Validation failed. Verify all required booking fields are provided and valid. |
    | `429` | `RESOURCE_EXHAUSTED` | `FEATURE_LIMIT_EXCEEDED` | The site has reached the limit for this feature. |
    | `428` | `FAILED_PRECONDITION` | `REFUND_NOT_ALLOWED` | Refunds aren't allowed for this booking. Check the booking's payment status and refund policy. |
    | `403` | `PERMISSION_DENIED` | `NOT_ALLOWED_TO_UPDATE_BOOKING_IN_MULTI_SERVICE_BOOKING` | This booking is part of a multi-service booking and can't be updated individually. Update the multi-service booking instead. |
