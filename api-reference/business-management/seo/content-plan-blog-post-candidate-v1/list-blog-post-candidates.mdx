    Retrieves a list of blog post candidates for a content plan flow.

    Omit `contentPlanFlowId` to read the site's most recent successful flow.
    A site whose flows are all still running, failed, or canceled returns a
    not found error.

    Omit `paging` to return every candidate in a single response. When
    `paging` is present, `limit` accepts 1 to 100 and defaults to 50.

    Results are sorted by the order the content plan assigns them, then by
    descending keyword score. The sort isn't configurable.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.PROMOTE.VIEW-SEO">View SEO Settings</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    GET https://www.wixapis.com/promote/seo/v1/content-plan-flows/{contentPlanFlowId}/blog-post-candidates
    ```

    ## Path Params

    <ParamField path="contentPlanFlowId" type="string" required>

      ID of the content plan flow to retrieve candidates for.

      Omit to read the site's most recent successful flow.

    </ParamField>

    ## Query Params

    <ParamField query="includeOnlyUnmarked" type="boolean">

      Whether to return only candidates that haven't been used for a blog post
      yet.

      A candidate is marked as used when a blog post is created from it in the
      Wix Blog product. An app can read this flag but can't set it, so track
      the posts you've written on your own side as well.

      Default: `false`, which returns every candidate.

    </ParamField>

    <ParamField query="paging" type="CursorPaging">

      Cursor paging. Omit for the first page.

      Omit this object entirely to return every candidate in a single response.

      <Expandable title="paging properties">

        <ParamField query="limit" type="integer">

          Max items per page. Default 50, max 100.

        </ParamField>

        <ParamField query="cursor" type="string">

          Cursor from a previous response. Omit for the first page.

        </ParamField>

      </Expandable>

    </ParamField>

    ## Response Object

    <ResponseField name="blogPostCandidates" type="BlogPostCandidate[]">

      Retrieved blog post candidates.

      Constraints: `maxItems 1000`.

      See the [Content Plan Blog Post Candidate Object](/api-reference/business-management/seo/content-plan-blog-post-candidate-v1/content-plan-blog-post-candidate-object) for this object's fields.

    </ResponseField>

    <ResponseField name="pagingMetadata" type="CursorPagingMetadata">

      Paging metadata.

      <Expandable title="pagingMetadata properties">

        <ResponseField name="count" type="integer">

          Items returned in this page.

        </ResponseField>

        <ResponseField name="cursors" type="Cursors">

          Cursors for next/previous page.

          <Expandable title="cursors properties">

            <ResponseField name="next" type="string">

              Cursor for the next page.

            </ResponseField>

            <ResponseField name="prev" type="string">

              Cursor for the previous page.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="hasNext" type="boolean">

          Whether there are more pages.

        </ResponseField>

      </Expandable>

    </ResponseField>
