    Retrieves the variables a pattern for a page type may reference.

    Call this method to retrieve the valid variables for a page type before writing a
    pattern.

    Variables for the page's own tags and variables for its structured data are returned
    in separate fields, and a pattern may use either.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.PROMOTE.VIEW-SEO">View SEO Settings</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    GET https://www.wixapis.com/promote/seo/v1/seo-patterns/{pageType}/variables
    ```

    ## Path Params

    <ParamField path="pageType" type="string" required>

      Page type whose variables to retrieve. For example, `STATIC_PAGE`, `BLOG_POST`, or
      `STORES_PRODUCT`.

    </ParamField>

    ## Response Object

    <ResponseField name="variables" type="SeoPatternVariable[]">

      Variables a pattern for this page type may use in its tags. For example,
      `{{product.name}}` in a title template.

      A variable can appear more than once, with different `userVisible` values, when both
      the site and the page type offer it. Either entry can be used in a pattern.

      Constraints: `maxItems 500`.

      <Expandable title="variables properties">

        <ResponseField name="key" type="string">

          Name of the variable, without the surrounding braces. For example, `product.name`,
          which a pattern references as `{{product.name}}`.

          Constraints: `maxLength 200`.

        </ResponseField>

        <ResponseField name="userVisible" type="boolean">

          Whether the variable appears in the list shown to Wix users editing the pattern in the
          dashboard.

          `false` doesn't prevent a pattern from using the variable. It marks a variable that's
          kept out of the dashboard's list, typically because it's only meaningful in certain
          cases.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="structuredDataVariables" type="SeoPatternVariable[]">

      Variables a pattern for this page type may use in its structured data tags.

      A pattern may use these as well as the variables in `variables`.

      Constraints: `maxItems 500`.

      <Expandable title="structuredDataVariables properties">

        <ResponseField name="key" type="string">

          Name of the variable, without the surrounding braces. For example, `product.name`,
          which a pattern references as `{{product.name}}`.

          Constraints: `maxLength 200`.

        </ResponseField>

        <ResponseField name="userVisible" type="boolean">

          Whether the variable appears in the list shown to Wix users editing the pattern in the
          dashboard.

          `false` doesn't prevent a pattern from using the variable. It marks a variable that's
          kept out of the dashboard's list, typically because it's only meaningful in certain
          cases.

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `400` | `INVALID_ARGUMENT` | `UNSUPPORTED_PAGE_TYPE` | Wix doesn't recognize the specified `pageType`. The error message lists the page types that are supported. |
    | `404` | `NOT_FOUND` | `PAGE_TYPE_NOT_ON_SITE` | The page type is valid, but the Wix business solution that provides it isn't installed on the site. |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>

    ## Examples

    `page.isHomePage` and `site.business.location.city` have `userVisible` set to false, which keeps them out of the dashboard's list but doesn't stop a pattern from using them.

    <CodeGroup>

      ```bash Request
      curl -X GET \
      'https://www.wixapis.com/seo-metatags-server/v1/seo-patterns/STATIC_PAGE/variables' \
      -H 'Authorization: <AUTH>' \
      -H 'Content-Type: application/json'
      ```

      ```json Response
      {
        "variables": [
          {
            "key": "page.name",
            "userVisible": true
          },
          {
            "key": "page.url",
            "userVisible": true
          },
          {
            "key": "site.name",
            "userVisible": true
          },
          {
            "key": "site.business.name",
            "userVisible": true
          },
          {
            "key": "site.image",
            "userVisible": true
          },
          {
            "key": "page.isHomePage",
            "userVisible": false
          }
        ],
        "structuredDataVariables": [
          {
            "key": "site.url",
            "userVisible": true
          },
          {
            "key": "site.business.location.city",
            "userVisible": false
          }
        ]
      }
      ```
