---
title: "Pipeline Object"
description: "A structured business process workflow consisting of multiple ordered stages and a final stage."
icon: "cube"
---

A structured business process workflow consisting of multiple ordered stages and a final stage.

Pipelines define the path that cards (deals, leads, projects, etc.) follow from start to completion.
Each pipeline has a currency setting that applies to all monetary values within that pipeline.
Pipeline stages can be configured with stale duration settings to identify workflow delays.

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Pipeline ID.

      **Read-only.**

    </ResponseField>

    <ResponseField name="revision" type="integer">

      Revision number, which increments by 1 each time the pipeline is updated.
      To prevent conflicting changes, the current revision must be passed when updating the pipeline.

      Ignored when creating a pipeline.

      **Read-only.**

    </ResponseField>

    <ResponseField name="createdDate" type="datetime">

      Date and time the pipeline was created in [ISO-8601](https://en.wikipedia.org/wiki/ISO_8601#combined_date_and_time_representations) format.

      **Read-only.**

    </ResponseField>

    <ResponseField name="updatedDate" type="datetime">

      Date and time the pipeline was last updated in [ISO-8601](https://en.wikipedia.org/wiki/ISO_8601#combined_date_and_time_representations) format.

      **Read-only.**

    </ResponseField>

    <ResponseField name="name" type="string">

      Pipeline name.

    </ResponseField>

    <ResponseField name="currency" type="string">

      Currency code for monetary values in this pipeline. Must be a valid ISO 4217 currency code. For example, `USD`.

      Default: Based on the site's currency settings.

    </ResponseField>

    <ResponseField name="stages" type="Stage[]">

      Pipeline stages in order.
      Cards move through these stages as they progress through the business process.

      Constraints: `minItems 1`, `maxItems 30`.

      <Expandable title="stages properties">

        <ResponseField name="id" type="string">

          Stage ID.

          **Read-only.**

        </ResponseField>

        <ResponseField name="name" type="string">

          Stage name.

        </ResponseField>

        <ResponseField name="staleDurationInHours" type="integer">

          The duration (in hours) a card can remain in this stage before becoming stale.
          When a card exceeds this duration, it's marked as stale to indicate potential workflow delays.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="doneStage" type="DoneStage">

      The final pipeline stage where cards receive a final outcome.

      <Expandable title="doneStage properties">

        <ResponseField name="id" type="string">

          Done stage ID.

          **Read-only.**

        </ResponseField>

        <ResponseField name="name" type="string">

          Done stage name.

        </ResponseField>

        <ResponseField name="allowedOutcomes" type="string[]">

          Outcomes that cards can have when moved to the done stage.

          Constraints: `minItems 1`, `maxItems 3`.

          **Supported values:**

          - `NONE` — No specific outcome. The process reached the final stage but has not been specified as successful or unsuccessful.
          - `WON` — Successful outcome. The process achieved its intended goal.
          - `LOST` — Unsuccessful outcome. The process didn't achieve its intended goal.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="source" type="PipelineSource">

      The app that created this pipeline.

      **Read-only.**

      <Expandable title="source properties">

        <ResponseField name="appId" type="string">

          ID of the app that created this pipeline.

          **Read-only.**

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="extendedFields" type="ExtendedFields">

      Extended fields data.

      <Expandable title="extendedFields properties">

        <ResponseField name="namespaces" type="object">

          Extended field data. Each key corresponds to the namespace of the app that created the extended fields.
          The value of each key is structured according to the schema defined when the extended fields were configured.

          You can only access fields for which you have the appropriate permissions.

          Learn more about [extended fields](https://dev.wix.com/docs/rest/articles/getting-started/extended-fields).

          Constraints: `format map`.

          <Expandable title="namespaces properties">

            <ResponseField name="key" type="string" />

            <ResponseField name="value" type="object" />

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="tags" type="PrivateTags">

      Tags for organizing and categorizing pipelines.

      <Expandable title="tags properties">

        <ResponseField name="privateTags" type="TagList">

          Tags that are exposed to anyone with access to the entity, including site members and visitors.

          <Expandable title="privateTags properties">

            <ResponseField name="tagIds" type="string[]">

              List of tag IDs.

              Constraints: `maxLength 5`, `maxItems 100`.

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>
