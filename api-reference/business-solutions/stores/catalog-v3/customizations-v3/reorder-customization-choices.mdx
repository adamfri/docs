    Sets the display order of a customization's choices.

    Each time the customization is updated, `revision` increments by 1. The current `revision` must be passed when updating the customization. This ensures you're working with the latest customization and prevents unintended overwrites.

    The new order is persisted in the customization's `choices` list. Calling this method also sets `choicesSettings.sortOrder` to `MANUAL`.

    To change how choices are sorted in storefront filter panels without specifying an explicit order, call [Update Customization](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/customizations-v3/update-customization) and set the `choicesSettings.sortOrder` field.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.STORES.CUSTOMIZATION_WRITE">Customization write in v3 catalog</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/stores/v3/customizations/{customizationId}/reorder-choices
    ```

    ## Path Params

    <ParamField path="customizationId" type="string" required>

      Customization ID.

    </ParamField>

    ## Body Params

    <ParamField body="revision" type="string" required>

      Revision number, which increments by 1 each time the customization is updated. To prevent conflicting changes, the current revision must be passed when updating the customization.

    </ParamField>

    <ParamField body="choiceIds" type="string[]" required>

      Choice IDs in the desired display order. Must contain exactly the same IDs as the customization's current choices, with no additions, removals, or duplicates.

      Constraints: `format GUID`, `minItems 1`, `maxItems 1000`.

    </ParamField>

    <ParamField body="fields" type="string[]">

      Fields to include in the response.

      Supported values: `ASSIGNED_PRODUCTS_COUNT`.

      Constraints: `maxItems 100`.

      **Supported values:**

      - `ASSIGNED_PRODUCTS_COUNT` — Assigned products count.
      - `CHOICE_DISPLAY_IMAGE` — Returns display images for choices.

    </ParamField>

    ## Response Object

    <ResponseField name="customization" type="Customization">

      Updated customization, with `choices` in the new order and `choicesSettings.sortOrder` set to `MANUAL`.

      See the [Customization Object](/api-reference/business-solutions/stores/catalog-v3/customizations-v3/customization-object) for this object's fields.

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `400` | `INVALID_ARGUMENT` | `DOESNT_SUPPORT_CHOICES` | Customization's `renderType` is `FREE_TEXT`, which doesn't support choices. Use a customization with the `SWATCH_CHOICES` or `TEXT_CHOICES` render type instead. |
    | `400` | `INVALID_ARGUMENT` | `CHOICE_IDS_MISMATCH` | `choiceIds` doesn't match the customization's current choices. See `ChoiceIdsMismatchData` in the error details for the specific IDs that are missing or extra. |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
