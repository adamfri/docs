title: "Content Plan Blog Post Candidate Object"
description: "A blog post candidate is a single blog post brief in a site's content plan."
icon: "cube"
---

A blog post candidate is a single blog post brief in a site's content plan.

Each candidate pairs a target keyword with a suggested title, the search
data behind that keyword, and the site page the post should support. A site
owner uses a candidate as the starting point for writing a post.

Candidates are generated by the content plan pipeline and are read-only.
Call Create Content Plan to generate them, and List Blog Post Candidates to
read them.

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Blog post candidate ID.

      Treat this value as opaque. Don't parse it or build it yourself, and
      pass it back exactly as received. The individual IDs it's built from are
      available on `candidateData`.

      **Read-only.**

    </ResponseField>

    <ResponseField name="candidateData" type="CandidateData">

      IDs that identify the candidate and the flow that generated it.

      <Expandable title="candidateData properties">

        <ResponseField name="blogPostCandidateId" type="string">

          ID of the blog post candidate within its content plan flow.

          **Read-only.**

        </ResponseField>

        <ResponseField name="contentPlanFlowId" type="string">

          ID of the content plan flow that generated this candidate.

          **Read-only.**

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="briefData" type="BriefData">

      The blog post brief itself: the suggested title, the target keywords,
      and the search data behind them.

      <Expandable title="briefData properties">

        <ResponseField name="h1Title" type="string">

          Suggested title for the blog post.

        </ResponseField>

        <ResponseField name="keyword" type="string">

          Keyword the blog post targets.

        </ResponseField>

        <ResponseField name="mainKeyword" type="string">

          Primary keyword for the page the blog post supports.

          A page has a single main keyword, and several blog posts can support the
          same one.

        </ResponseField>

        <ResponseField name="serpData" type="SerpData">

          Search engine results data for `mainKeyword`, such as its search volume
          and how hard it is to rank for.

          List Blog Post Candidates doesn't currently return this field.

          <Expandable title="serpData properties">

            <ResponseField name="id" type="string">

              SerpDataResult ID

              **Read-only.**

            </ResponseField>

            <ResponseField name="peopleAlsoAskSuggestions" type="PeopleAlsoAskQuestion[]">

              list of people also ask questions

              Constraints: `maxItems 4`.

              <Expandable title="peopleAlsoAskSuggestions properties">

                <ResponseField name="question" type="string">

                  people also ask question title

                </ResponseField>

                <ResponseField name="answers" type="PeopleAlsoAskAnswer[]">

                  answers to the question

                  Constraints: `maxItems 2`.

                  _Nested structure omitted for brevity — see the `PeopleAlsoAskAnswer[]` object._

                </ResponseField>

              </Expandable>

            </ResponseField>

            <ResponseField name="peopleAlsoSearchSuggestions" type="string[]">

              list of related searches

              Constraints: `maxLength 10000`, `maxItems 10`.

            </ResponseField>

            <ResponseField name="autocompleteSuggestions" type="string[]">

              list of autocomplete suggestions

              Constraints: `maxLength 10000`, `maxItems 15`.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="pageUrl" type="string">

          URL of the site page the blog post is meant to support.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="seoData" type="SeoSchema">

      SEO tags suggested for the blog post, such as its title tag and meta
      description.

      <Expandable title="seoData properties">

        <ResponseField name="tags" type="Tag[]">

          SEO tag information.

          <Expandable title="tags properties">

            <ResponseField name="type" type="string">

              SEO tag type.

              Supported values: `title`, `meta`, `script`, `link`.

              Which of these an API actually accepts depends on where the tag is being set: this
              list is not a blanket guarantee across every API that reuses this message. Site SEO
              Tags in particular accepts only `meta` (see `SiteSeoTags.tags`) and rejects
              `title`/`script`/`link` with a validation error even though they appear here —
              check the field description of the specific `tags`-typed field you're writing to
              for the types it actually supports and the error it returns.

              Limitation: `title` and `script` (e.g. a `script` tag with `props.type`
              `"application/ld+json"` carrying structured data) are supported only when
              `custom` is unset or `false`. Setting `custom: true` on a `title` or `script`
              tag is rejected with `TAG_TYPE_NOT_ALLOWED`, because `custom: true` routes the
              write through the site's Advanced/Custom Tags list. To write structured data,
              omit `custom` (or set it to `false`).

            </ResponseField>

            <ResponseField name="props" type="object">

              A `{"key": "value"}` pair object where each SEO tag property (`"name"`, `"content"`, `"rel"`, `"href"`) contains a value.
              For example: `{"name": "description", "content": "the description itself"}`.

            </ResponseField>

            <ResponseField name="meta" type="object">

              SEO tag metadata. For example, `{"height": 300, "width": 240}`.

            </ResponseField>

            <ResponseField name="children" type="string">

              SEO tag inner content. For example, `<title> inner content </title>`.

            </ResponseField>

            <ResponseField name="custom" type="boolean">

              Whether the tag is a [custom tag](https://support.wix.com/en/article/adding-additional-meta-tags-to-your-sites-pages) —
              i.e. an entry from the site's Advanced/Custom Tags list.

              Setting this to `true` on a write restricts which `type` values are accepted
              — the same restriction the Advanced/Custom Tags UI enforces. `title` and
              `script` tags (including JSON-LD structured data) must be sent with `custom`
              omitted or `false`; sending them with `custom: true` is rejected with
              `TAG_TYPE_NOT_ALLOWED`.

              Note this is a separate restriction from Site SEO Tags' own type restriction on
              `SiteSeoTags.tags`: even with `custom` unset, Site SEO Tags rejects `script` (e.g.
              for site-wide structured data) unconditionally. There is currently no way to set
              site-wide, every-page structured data through any of these APIs — write a per-page
              `script` tag through the Item SEO Tags API instead.

              This flag is scoped to that feature only. It is NOT an indicator of whether a standard tag
              (`title`, `description`, Open Graph, etc.) reflects a manually configured value versus a computed
              default/pattern — standard tags always resolve with `custom: false`, even when their content comes
              from a page's manually saved SEO title/description override. Don't use this field to verify whether
              a live page reflects a manual per-page SEO edit.

              Limitation: when `ResolveStaticPageSeoTags` is called without `seoData`, the per-page SEO data is read
              only from the Vibe/Wix-managed-headless override store. That store holds nothing for classic Wix Editor
              or Wix Studio pages, so even genuine Advanced/Custom Tags saved on those pages are missing from the
              response entirely — there, `false` means this API could not tell, not that no custom tag exists.
              Pass `seoData` explicitly to resolve against a known set of tags.

            </ResponseField>

            <ResponseField name="disabled" type="boolean">

              Whether the tag is disabled. If the tag is disabled, people can't find your page when searching for this phrase in search engines.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="settings" type="Settings">

          SEO general settings.

          <Expandable title="settings properties">

            <ResponseField name="preventAutoRedirect" type="boolean">

              Whether the [automatical redirect visits](https://support.wix.com/en/article/customizing-your-pages-seo-settings-in-the-seo-panel) from the old URL to the new one is enabled.

              Default: `false` (automatical redirect is enabled).

            </ResponseField>

            <ResponseField name="keywords" type="Keyword[]">

              User-selected keyword terms for a specific page.

              Constraints: `maxItems 5`.

              <Expandable title="keywords properties">

                <ResponseField name="term" type="string">

                  Keyword value.

                </ResponseField>

                <ResponseField name="isMain" type="boolean">

                  Whether the keyword is the main focus keyword.

                </ResponseField>

                <ResponseField name="origin" type="string">

                  The source that added the keyword terms to the SEO settings.

                </ResponseField>

              </Expandable>

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Example

    <CodeGroup>

      ```json Object
      {
        "blogPostCandidate": {
          "id": "d290f1ee-6c54-4b01-90e6-d701748f0851_7c41b0a2",
          "candidateData": {
            "blogPostCandidateId": "7c41b0a2-9d3e-4f18-b6a5-2ec80d947f31",
            "contentPlanFlowId": "d290f1ee-6c54-4b01-90e6-d701748f0851"
          },
          "briefData": {
            "h1Title": "10 Best Coffee Beans for Home Brewing in 2026",
            "keyword": "best coffee beans home brewing",
            "mainKeyword": "coffee beans",
            "serpData": {
              "id": "5b2e9f04-71ca-42d7-8f3b-1d60ae35c982",
              "peopleAlsoAskSuggestions": [
                {
                  "question": "What coffee beans are best for home use?",
                  "answers": [
                    {
                      "title": "Top picks",
                      "description": "Arabica beans from Ethiopia and Colombia are widely recommended for home brewing."
                    }
                  ]
                }
              ],
              "peopleAlsoSearchSuggestions": [
                "arabica vs robusta",
                "how to store coffee beans"
              ],
              "autocompleteSuggestions": [
                "best coffee beans 2026",
                "best coffee beans for espresso"
              ]
            },
            "pageUrl": "https://www.example.com/shop/coffee-beans"
          },
          "seoData": {
            "tags": [
              {
                "type": "title",
                "children": "10 Best Coffee Beans for Home Brewing in 2026",
                "custom": false,
                "disabled": false
              },
              {
                "type": "meta",
                "props": {
                  "name": "description",
                  "content": "Compare the best coffee beans for home brewing in 2026, ranked by flavor, roast, and price."
                },
                "custom": false,
                "disabled": false
              }
            ],
            "settings": {
              "preventAutoRedirect": false,
              "keywords": [
                {
                  "term": "best coffee beans home brewing",
                  "isMain": true,
                  "origin": "CONTENT_PLAN"
                }
              ]
            }
          }
        }
      }
      ```

    </CodeGroup>
