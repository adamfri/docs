    <div className="wix-ref">

    Retrieves a list of all backups for a site.

    Results are sorted by requested date, with the newest first.

    You can use this method to check whether a backup initiated with Create Backup has been completed successfully.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.DC-DATA.MANAGE-BACKUPS">Manage Data Backups</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    GET https://www.wixapis.com/wix-data/v2/backups
    ```

    ## Query Params

    <ParamField query="status" type="string[]">

      Statuses to filter by.
      If provided, only backups with the specified statuses are listed.
      For example, to list only completed backups, use `?status=READY`.
      To list completed and pending backups, use `?status=READY&status=PENDING`.

      Default: No filtering

      Constraints: `maxItems 10`.

      **Supported values:**

      - `PENDING` — Backup creation is in progress.
      - `READY` — Backup has been created successfully and can be used for data restoration.
      - `FAILED` — Backup creation has failed.
      - `DELETED` — Backup has been deleted.
      - `CANCELED` — Backup has been canceled.

    </ParamField>

    <ParamField query="type" type="string[]">

      Type to filter by. If provided, only backups of the specified type are listed.

      Default: No filtering

      Constraints: `maxItems 10`.

      **Supported values:**

      - `ON_DEMAND` — Backup taken on demand.
      - `AUTO` — Backup taken automatically by the system on a regular schedule.

    </ParamField>

    <ParamField query="paging" type="Paging">

      Paging preferences.

      <Expandable title="paging properties">

        <ParamField query="limit" type="integer">

          Number of items to load.

        </ParamField>

        <ParamField query="offset" type="integer">

          Number of items to skip in the current sort order.

        </ParamField>

      </Expandable>

    </ParamField>

    ## Response Object

    <ResponseField name="backups" type="Backup[]">

      Retrieved backups.

      Constraints: `maxItems 1000`.

      <Expandable title="backups properties">

        <ResponseField name="id" type="string">

          Backup ID.

          **Read-only.** Constraints: `format GUID`.

        </ResponseField>

        <ResponseField name="status" type="string">

          Backup status.

          **Read-only.**

          **Supported values:**

          - `PENDING` — Backup creation is in progress.
          - `READY` — Backup has been created successfully and can be used for data restoration.
          - `FAILED` — Backup creation has failed.
          - `DELETED` — Backup has been deleted.
          - `CANCELED` — Backup has been canceled.

        </ResponseField>

        <ResponseField name="type" type="string">

          Type of backup, based on how it was triggered.

          **Read-only.**

          **Supported values:**

          - `ON_DEMAND` — Backup taken on demand.
          - `AUTO` — Backup taken automatically by the system on a regular schedule.

        </ResponseField>

        <ResponseField name="requestedDate" type="datetime">

          Date and time the backup was requested.

          **Read-only.**

        </ResponseField>

        <ResponseField name="startedDate" type="datetime">

          Date and time the backup commenced. Value is `null` until the backup process begins in the background.

          **Read-only.**

        </ResponseField>

        <ResponseField name="finishedDate" type="datetime">

          Date and time the backup process finished. Value is `null` until the backup process is completed in the background.

          **Read-only.**

        </ResponseField>

        <ResponseField name="deletedDate" type="datetime">

          Date and time the backup was deleted. Value is `null` if that backup hasn't been deleted.

          **Read-only.**

        </ResponseField>

        <ResponseField name="sizeInBytes" type="integer">

          Backup size in bytes. Value is `null` until the backup process is completed.

          **Read-only.**

        </ResponseField>

        <ResponseField name="collections" type="Collection[]">

          IDs and display names of collections the backup contains.

          **Read-only.** Constraints: `maxItems 1000`.

          <Expandable title="collections properties">

            <ResponseField name="id" type="string">

              Collection ID.

              **Read-only.** Constraints: `maxLength 255`.

            </ResponseField>

            <ResponseField name="displayName" type="string">

              Collection display name.

              **Read-only.**

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="pagingMetadata" type="PagingMetadataV2">

      Paging information.

      <Expandable title="pagingMetadata properties">

        <ResponseField name="count" type="integer">

          Number of items returned in the response.

        </ResponseField>

        <ResponseField name="offset" type="integer">

          Offset that was requested.

        </ResponseField>

        <ResponseField name="total" type="integer">

          Total number of items that match the query. Returned if offset paging is used and the `tooManyToCount` flag is not set.

        </ResponseField>

        <ResponseField name="tooManyToCount" type="boolean">

          Flag that indicates the server failed to calculate the `total` field.

        </ResponseField>

      </Expandable>

    </ResponseField>
