<Note>This article applies to the REST API only.</Note>

This article covers field support for filtering in:

- [Query Staff Members](https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/query-staff-members).
- [Search Staff Members](https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/search-staff-members).
- [Count Staff Members](https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/count-staff-members).
- [Query Staff Members V2](fallback::https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/query-staff-members-v2).
- [Search Staff Members V2](fallback::https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/search-staff-members-v2).
- [Count Staff Members V2](fallback::https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/count-staff-members-v2).
- [Bulk Update Staff Member Tags By Filter](https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/bulk-update-staff-member-tags-by-filter).

Each V2 method supports the same fields, operators, and sorting as its V1 counterpart: Query Staff
Members V2 matches Query Staff Members, Search Staff Members V2 matches Search Staff Members, and
Count Staff Members V2 matches Count Staff Members. They differ only in which staff members they
return by default: the V1 methods return service providers only unless you pass an explicit
`serviceProvider` filter, while the V2 methods return the entire staff. To narrow V2 results to
service providers, filter by `serviceProvider`.

The Query methods and the Search methods accept the same fields for filtering. They differ in
sorting only: `name`, `email`, and `phone` are personally identifiable, and can be sorted on in the
Search methods but not in the Query methods.

## Filtering

Specify the `filter` object in the following format:

```json
{
  "filter": {
    "fieldName": {
      "$eq": "value"
    }
  }
}
```

The following table shows field support for filters and sorting for the `staffMember` object:

| Field | Supported Filters | Sortable |
|-------|-------------------|----------|
| `id` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$startsWith`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `description` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$startsWith`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `resourceId` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$startsWith`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `serviceProvider` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome` | Sortable |
| `createdDate` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `updatedDate` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `associatedWixIdentity.identificationData.contactId` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$startsWith`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `associatedWixIdentity.identificationData.wixUserId` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$startsWith`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `associatedWixIdentity.identificationData.identityType` | `$eq`, `$ne`, `$exists`, `$in`, `$nin`, `$hasSome`, `$startsWith`, `$gt`, `$lt`, `$lte`, `$gte` | Sortable |
| `name` | `$eq`, `$ne`, `$exists`, `$in`, `$nin` | Search methods only |
| `email` | `$eq`, `$ne`, `$exists`, `$in`, `$nin` | Search methods only |
| `phone` | `$eq`, `$ne`, `$exists`, `$in`, `$nin` | Search methods only |
| `resource.locationOptions.specificLocationOptions.businessLocations.locationId` | `$hasSome`, `$hasAll` | |
| `resource.locationOptions.specificLocationOptions.businessLocations` | `$isEmpty` | |

`name`, `email`, and `phone` hold personally identifiable information. You can sort on them in
[Search Staff Members](https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/search-staff-members)
and [Search Staff Members V2](fallback::https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/search-staff-members-v2).
The Query methods reject a sort on any of them with an `INVALID_SORT` error.

The Search methods additionally match the `search` expression against the staff member's `name`.

### Filter a staff member by whether they provide services

`serviceProvider` marks whether customers can book the staff member. Filter on it to separate the
business's service providers from the rest of its team:

```json
{
  "filter": {
    "serviceProvider": true
  }
}
```

## Sorting

When you don't specify a sort, results in
[Query Staff Members](https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/query-staff-members),
[Search Staff Members](https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/search-staff-members),
[Query Staff Members V2](fallback::https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/query-staff-members-v2),
and [Search Staff Members V2](fallback::https://dev.wix.com/docs/rest/business-solutions/bookings/staff-members/search-staff-members-v2)
are sorted by the `id` field in ascending order.

To sort by a different field, use the `sort` object in the following format:

```json
{
  "sort": [
    {
      "fieldName": "description",
      "order": "DESC"
    }
  ]
}
```
