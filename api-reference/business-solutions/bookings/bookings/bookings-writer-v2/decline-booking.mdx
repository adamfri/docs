    Updates the booking status to `DECLINED` without checking whether the relevant slot or schedule is still available.

    ### eCommerce checkout restriction

    Call this method only when using a custom checkout page.
    Don't call it when using a [Wix eCommerce checkout](https://dev.wix.com/docs/rest/business-solutions/e-commerce/checkout/introduction).
    In such cases, Wix Bookings automatically updates the booking status based on the `paymentStatus` of the corresponding [Wix eCommerce order](https://dev.wix.com/docs/rest/business-solutions/e-commerce/orders/introduction).

    ### When to call Decline Booking

    When using a custom checkout, call this method to decline bookings that don't have a double booking conflict.
    The alternative [Confirm or Decline Booking](https://dev.wix.com/docs/rest/business-solutions/bookings/bookings/bookings-writer-v2/confirm-or-decline-booking) method doesn't support this scenario.

    ### When to call Confirm Or Decline Booking instead

    Decline Booking doesn't check whether a slot or schedule is still available.
    For these checks you can call [Confirm or Decline Booking](https://dev.wix.com/docs/rest/business-solutions/bookings/bookings/bookings-writer-v2/confirm-or-decline-booking).

    ### Original status validation

    You can only decline bookings with a `status` of `PENDING`, `CREATED`, or
    `WAITING_LIST`.

    ### Payment status

    Also updates the booking's `paymentStatus`, if you specify a new payment
    status.

    ### Notify customers

    You can specify a `participantNotification.message` for the customer. To send
    the message, you must also specify `participantNotification.notifyParticipants`
    as `true`.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    <ParamField body="revision" type="integer" required>

      Revision number, which increments by 1 each time the booking is updated.

      To prevent conflicting changes, the current revision must be specified when
      declining the booking.

    </ParamField>

    <ParamField body="participantNotification" type="ParticipantNotification">

      Information about whether to notify the customer and
      the message to send.

      <Expandable title="participantNotification properties">

        <ParamField body="notifyParticipants" type="boolean">

          Whether to send a message about the changes to the customer.

          Default: `false`

        </ParamField>

        <ParamField body="message" type="string">

          Custom message to send to the participants about the changes to the booking.

        </ParamField>

        <ParamField body="metadata" type="object">

          Information about the delivery channels used to send the notification.
          For example, `{"channels": "SMS" }`, `{"channels": "EMAIL" }`, or `{"channels": "EMAIL, SMS" }`.

          Constraints: `format map`.

          <Expandable title="metadata properties">

            <ParamField body="key" type="string" />

            <ParamField body="value" type="string" />

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="paymentStatus" type="string">

      Payment status to set for the booking.

      **Supported values:**

      - `UNDEFINED` — Undefined payment status.
      - `NOT_PAID` — The booking isn't paid.
      - `PAID` — The booking is fully paid.
      - `PARTIALLY_PAID` — The booking is partially paid.
      - `REFUNDED` — The booking is refunded.
      - `EXEMPT` — The booking is free of charge.
      - `FAILED` — The most recent subscription payment for this booking failed. If the payment is later recovered, the status changes back to `PAID`. Returned only for course bookings with subscription pricing.

    </ParamField>

    <ParamField body="doubleBooked" type="boolean">

      Whether this booking has a conflict with at least 1 other confirmed booking.

    </ParamField>

    <ParamField body="flowControlSettings" type="DeclineBookingFlowControlSettings">

      Whether to ignore specific standard procedures of the Wix Bookings flow.
      For example, whether to refund a declined booking.

      <Expandable title="flowControlSettings properties">

        <ParamField body="withRefund" type="boolean">

          Whether a refund is expected when declining the booking.

          The refund will be issued only if the booking is refundable.
          A booking paid by membership is refunded by Wix Bookings itself.
          A booking paid by any other method is refunded by the site's refund automation, if one is set up.
          If specifying `true`, the booking flow control settings will be set with a refund.
          If you specify `false` or an empty field,
          the booking flow control settings are set without refund.

          Default: `false`.

        </ParamField>

      </Expandable>

    </ParamField>
