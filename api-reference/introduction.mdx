---

Every Wix API is generated from a single proto definition, then published in two flavours:

- a **REST API** you call over HTTP
- a **JavaScript SDK** you install from npm

They cover the same operations, but they are **not** field-for-field identical. The pipeline
applies JavaScript conventions on the SDK side, so the same operation can differ in field
names, argument shape, and return shape.

## Reading a reference page

Each operation page has a **REST** and an **SDK** tab. Pick the one that matches how
you're calling the API.

The two tabs use different vocabulary, matching each platform:

| REST | JavaScript SDK |
| --- | --- |
| Endpoint | Method Declaration |
| Path / Query / Body Params | Method Parameters |
| Response Object | Returns |

## What differs between the flavours

<AccordionGroup>
  <Accordion title="Field names" icon="tag">
    System fields are prefixed with an underscore in the SDK. For example, on the
    **App Permission** object:

    | REST | JavaScript SDK |
    | --- | --- |
    | `createdDate` | `_createdDate` |
    | `updatedDate` | `_updatedDate` |
    | `id` | `_id` |
  </Accordion>

  <Accordion title="Argument shape" icon="brackets-curly">
    REST takes a flat request — query parameters or a single JSON body. The SDK takes the
    required values as positional arguments, with everything optional collected into a final
    `options` object.

    <CodeGroup>
    ```bash REST
    GET /apps/v1/app-permissions/v1/app-permissions?appId=...&consistent=true
    ```

    ```javascript JavaScript SDK
    appPermissions.listAppPermissions(appId, options);
    ```
    </CodeGroup>
  </Accordion>

  <Accordion title="Return shape" icon="arrow-left">
    REST returns a wrapper object named after the operation. The SDK usually resolves
    directly to the entity.

    | REST | JavaScript SDK |
    | --- | --- |
    | `CreateAppPermissionResponse` | `Promise<AppPermission>` |
  </Accordion>

  <Accordion title="Which pages exist" icon="list">
    The flavours don't always publish the same pages. The App Permissions REST reference has
    an **App Permission Object** page; the SDK reference instead has a **Setup** article and
    an **on-app-permission-deleted** event page.
  </Accordion>
</AccordionGroup>

<Note>
  Because the two flavours diverge, these pages are generated directly from the Wix Docs
  pipeline schemas rather than from a single OpenAPI document. See the POC plan for details.
</Note>

## Permissions

Every method lists the permission scopes it requires. An app must request these in the
[Dev Center](https://dev.wix.com/dc3/my-apps) before it can call the method.
