    Increases the available stock quantity for specified items.

    Use this method when inventory needs to be incremented due to order events such as order cancellation, refund, or order editing.
    This method does not validate stock levels and allows negative inventory to be corrected.

    ## Endpoint

    ```http
    POST /v1/increment
    ```

    ## Body Params

    <ParamField body="items" type="Item[]" required>

      Items for which to increase their available stock quantity.

      Constraints: `minItems 1`, `maxItems 300`.

      <Expandable title="items properties">

        <ParamField body="catalogReference" type="CatalogReference" required>

          Catalog reference that uniquely identifies the item.

          Contains the app ID and catalog item ID required to locate the specific item in the catalog.

          <Expandable title="catalogReference properties">

            <ParamField body="catalogItemId" type="string" required>

              ID of the item within the catalog it belongs to.

              Constraints: `minLength 1`, `maxLength 36`.

            </ParamField>

            <ParamField body="appId" type="string" required>

              ID of the app providing the catalog.

              You can get your app's ID from its page in the [app dashboard](https://dev.wix.com/dc3/my-apps/).

              For items from Wix catalogs, the following values always apply:
              + Wix Stores: `"215238eb-22a5-4c36-9e7b-e7c08025e04e"`
              + Wix Bookings: `"13d21c63-b5ec-5912-8397-c3a5ddb27a97"`
              + Wix Restaurants: `"9a5d83fd-8570-482e-81ab-cfa88942ee60"`

              Constraints: `minLength 1`.

            </ParamField>

            <ParamField body="options" type="object">

              Additional item details in `key:value` pairs.

              Use this optional field for more specificity with item selection. The values of the `options` field differ depending on which catalog is providing the items.

              For Wix Stores products, learn more about integrating with [Catalog V3](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/e-commerce-integration)
              or [Catalog V1](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v1/catalog/e-commerce-integration), depending on [the version the site uses](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-versioning/introduction).

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="locationId" type="string">

          Location ID where the inventory is managed.

          When not provided, the default location is used for inventory tracking.

        </ParamField>

        <ParamField body="quantity" type="integer" required>

          Quantity of the item to increment or decrement.

          For example, `5` to reduce availability by 5 units or increase availability by 5 units.

          Constraints: `min 1`, `max 100000`.

        </ParamField>

        <ParamField body="subscriptionItem" type="boolean" required>

          Whether the item is part of a subscription order.

          Subscription items may be processed differently by inventory systems depending on their recurring nature.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="orderId" type="string" required>

      Order ID associated with this inventory change.

      Constraints: `format GUID`.

    </ParamField>

    <ParamField body="reason" type="string" required>

      Reason for the inventory increment.

      **Supported values:**

      - `ORDER_PLACED` — Order was placed by a customer.
      - `ORDER_PAID` — Order was paid for by a customer.
      - `ORDER_CANCELED` — Order was canceled.
      - `ORDER_REFUNDED` — Order was refunded.
      - `ORDER_EDITED` — Order was edited by a merchant.
      - `ORDER_REJECTED` — Order was rejected.

    </ParamField>

    ## Response Object

    Returns `IncrementAvailabilityResponse`.

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `428` | `FAILED_PRECONDITION` | `INCREMENT_NOT_POSSIBLE` | Cannot increment availability due to invalid request parameters. |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
