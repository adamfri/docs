    Retrieves a list of products, given the provided filtering, search expression, sorting, and cursor paging.

    Provides eventually consistent results optimized for product discovery and browsing.
    Search supports full-text queries, filters, sorting, and aggregations for faceted search.

    Use Search Products for user-facing product catalogs and discovery features.
    For real-time accuracy in operational tasks, use [Query Products](https://dev.wix.com/docs/api-reference/business-solutions/suppliers-hub/products/query-products) instead.

    ## Body Params

    <ParamField body="search" type="CursorSearch">

      Search parameters including filter, sort, full-text search, and aggregations.

      <Expandable title="search properties">

        <ParamField body="filter" type="object">

          A filter object. See documentation [here](https://bo.wix.com/wix-docs/rnd/platformization-guidelines/api-query-language#platformization-guidelines_api-query-language_defining-in-protobuf)

        </ParamField>

        <ParamField body="sort" type="Sorting[]">

          Sort object in the form [&#123;"fieldName":"sortField1"&#125;,&#123;"fieldName":"sortField2","direction":"DESC"&#125;]

          Constraints: `maxItems 10`.

          <Expandable title="sort properties">

            <ParamField body="fieldName" type="string">

              Name of the field to sort by.

              Constraints: `maxLength 512`.

            </ParamField>

            <ParamField body="order" type="string">

              Sort order.

              **Supported values:**

              - `ASC`
              - `DESC`

            </ParamField>

            <ParamField body="selectItemsBy" type="object[]">

              Filters to specify which element to use for sorting when `fieldName` refers to a repeated field marked as `MATCH_ITEMS`.

              These filters ensure the correct element is selected from the collection for sorting. Multiple filters are combined using the `AND` operator.

              For example, for a document like `{"id": "1", "nestedField": [{"price": 10, "region": "EU"}, {"price": 20, "region": "US"}]}`,
              if `nestedField` is marked as `MATCH_ITEMS`, sorting by price in the US region requires:
              `{fieldName: "nestedField.price", "selectItemsBy": [{"nestedField.region": "US"}]}`.

              Constraints: `maxItems 10`.

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="aggregations" type="Aggregation[]">

          Aggregations | Faceted search: refers to a way to explore large amounts of data by displaying summaries about various partitions of the data and later allowing to narrow the navigation to a specific partition.

          Constraints: `maxItems 10`.

          <Expandable title="aggregations properties">

            <ParamField body="name" type="string">

              User-defined name of aggregation, should be unique, will appear in aggregation results

            </ParamField>

            <ParamField body="type" type="string">

              Type of aggregation, client must provide matching aggregation field below

              **Supported values:**

              - `VALUE` — An aggregation where result buckets are dynamically built - one per unique value
              - `RANGE` — An aggregation, where user can define set of ranges - each representing a bucket
              - `SCALAR` — A single-value metric aggregation - e.g. min, max, sum, avg
              - `DATE_HISTOGRAM` — An aggregation, where result buckets are dynamically built - one per time interval (hour, day, week, etc.)
              - `NESTED` — Multi-level aggregation, where each next aggregation is nested within previous one

            </ParamField>

            <ParamField body="fieldPath" type="string">

              Field to aggregate by, use dot notation to specify json path

              Constraints: `maxLength 200`.

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="search" type="SearchDetails">

          Free text to match in searchable fields

          <Expandable title="search properties">

            <ParamField body="expression" type="string">

              Search term or expression

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="timeZone" type="string">

          UTC offset or IANA time zone. Valid values are
          ISO 8601 UTC offsets, such as +02:00 or -06:00,
          and IANA time zone IDs, such as Europe/Rome

          Affects all filters and aggregations returned values.
          You may override this behavior in a specific filter by providing
          timestamps including time zone. e.g. `"2023-12-20T10:52:34.795Z"`

        </ParamField>

      </Expandable>

      <Expandable title="One of the following">

        <ParamField body="pagingMethod" type="pagingMethod">

              Cursor pointing to page of results.
              When requesting 'cursor_paging.cursor', no `filter`, `sort` or `search` can be provided.

              _Nested structure omitted for brevity — see the `CursorPaging` object._

            </ParamField>

          </Expandable>

        </ParamField>

      ```bash Request

            "limit": 5
      ```
