    <div className="wix-ref">

    Removes items from a benefit. The service removes items asynchronously. They may briefly still appear in
    Query Pool Definition Items results after the call returns.
    Item references not matching any registered item appear in results as per-item failures with `itemMetadata.error.code` set to `NOT_FOUND`.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.BENEFIT_PROGRAMS.MANAGE">Manage benefit programs</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/benefit-programs/v1/pool-definition-items/remove-items-from-benefit
    ```

    ## Body Params

    <ParamField body="itemReferences" type="ItemReference[]" required>

      Items to remove from the benefit's item set.

      Constraints: `minItems 1`, `maxItems 100`.

      <Expandable title="itemReferences properties">

        <ParamField body="externalId" type="string" required>

          External item ID assigned by the provider.

          Constraints: `format GUID`.

        </ParamField>

        <ParamField body="category" type="string">

          Item category.

          Constraints: `maxLength 20`.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="poolDefinitionId" type="string" required>

      ID of the pool definition associated with the benefit.

      Constraints: `format GUID`.

    </ParamField>

    <ParamField body="benefitKey" type="string" required>

      Key identifying the benefit in the pool definition.

      Constraints: `maxLength 64`.

    </ParamField>

    ## Response Object

    <ResponseField name="results" type="BulkRemoveItemResult[]">

      Per-item results aligned 1:1 with `itemReferences` from the request. `itemMetadata.originalIndex` always
      refers to the position in the request. Item references that didn't match any registered item appear here as
      failures with `itemMetadata.error.code` set to `NOT_FOUND`.

      <Expandable title="results properties">

        <ResponseField name="itemMetadata" type="ItemMetadata">

          Outcome metadata for a single item, including the underlying item ID, success flag, and error details on failure.

          <Expandable title="itemMetadata properties">

            <ResponseField name="id" type="string">

              Item ID. Should always be available, unless it's impossible (for example, when failing to create an item).

            </ResponseField>

            <ResponseField name="originalIndex" type="integer">

              Index of the item within the request array. Allows for correlation between request and response items.

            </ResponseField>

            <ResponseField name="success" type="boolean">

              Whether the requested action was successful for this item. When `false`, the `error` field is populated.

            </ResponseField>

            <ResponseField name="error" type="ApplicationError">

              Details about the error in case of failure.

              _Nested structure omitted for brevity — see the `ApplicationError` object._

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="bulkActionMetadata" type="BulkActionMetadata">

      Aggregate counts for the bulk operation, including successes and failures. The service counts unresolved item references as failures.

      <Expandable title="bulkActionMetadata properties">

        <ResponseField name="totalSuccesses" type="integer">

          Number of items that were successfully processed.

        </ResponseField>

        <ResponseField name="totalFailures" type="integer">

          Number of items that couldn't be processed.

        </ResponseField>

        <ResponseField name="undetailedFailures" type="integer">

          Number of failures without details because detailed failure threshold was exceeded.

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `404` | `NOT_FOUND` | `POOL_DEFINITION_BENEFIT_NOT_FOUND` | No benefit is configured for the given `poolDefinitionId` and `benefitKey` pair. |
