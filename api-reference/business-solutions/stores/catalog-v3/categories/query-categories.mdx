    Retrieves a list of up to 1,000 categories, given the provided filtering, sorting, and cursor paging.
    Pass supported values to the `fields` array in the request to include those fields in the response.

    To learn about working with _Query_ methods, see
    [API Query Language](https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/data-retrieval/about-the-wix-api-query-language),
    and [Sorting and Paging](https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/data-retrieval/about-sorting-and-paging).

    Learn more about the differences between [_Query_ and _Search_](https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/data-retrieval/about-search-query-and-list-methods) methods.

    | Property | Filters | Sort |
    | --- | --- | --- |
    | `id` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | None |
    | `slug` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | None |
    | `visible` | `$eq`, `$ne`, `$in`, `$exists` | None |
    | `treeReference.appNamespace` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | None |
    | `treeReference.treeKey` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | None |
    | `name` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `createdDate` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte` | Sort: `ASC`, `DESC` |
    | `updatedDate` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte` | Sort: `ASC`, `DESC` |
    | `managingAppId` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `parentCategory.id` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `parentCategory.index` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte` | Sort: `ASC`, `DESC` |

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.CATEGORIES.CATEGORY_READ">Read categories</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`, `MEMBER`, `VISITOR`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/categories/v1/categories/query
    ```

    ## Body Params

    <ParamField body="query" type="CursorQuery">

      Query options.

      <Expandable title="query properties">

        <ParamField body="filter" type="object">

          Filter object in the following format:
          `"filter" : {`
          "fieldName1": "value1",
          "fieldName2":&#123;"$operator":"value2"&#125;
          &#125;``
          Example of operators: `$eq`, `$ne`, `$lt`, `$lte`, `$gt`, `$gte`, `$in`, `$hasSome`, `$hasAll`, `$startsWith`, `$contains`

        </ParamField>

        <ParamField body="sort" type="Sorting[]">

          Sort object in the following format:
          `[{"fieldName":"sortField1","order":"ASC"},{"fieldName":"sortField2","order":"DESC"}]`

          Constraints: `maxItems 5`.

          <Expandable title="sort properties">

            <ParamField body="fieldName" type="string">

              Name of the field to sort by.

              Constraints: `maxLength 512`.

            </ParamField>

            <ParamField body="order" type="string">

              Sort order.

              **Supported values:**

              - `ASC` — Ascending order.
              - `DESC` — Descending order.

            </ParamField>

          </Expandable>

        </ParamField>

      </Expandable>

      <Expandable title="One of the following">

        <ParamField body="pagingMethod" type="pagingMethod">

          pagingMethod

          <Expandable title="pagingMethod properties">

            <ParamField body="cursorPaging" type="CursorPaging">

              Cursor token pointing to a page of results. Not used in the first request. Following requests use the cursor token and not `filter` or `sort`.

              _Nested structure omitted for brevity — see the `CursorPaging` object._

            </ParamField>

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="treeReference" type="TreeReference" required>

      Category tree reference details.

      <Expandable title="treeReference properties">

        <ParamField body="appNamespace" type="string" required>

          Namespace of the app whose catalog this category tree belongs to.

          Currently, only `"@wix/stores"` is supported.

          Constraints: `minLength 4`, `maxLength 150`.

        </ParamField>

        <ParamField body="treeKey" type="string">

          Key to differentiate between multiple trees managed by the same app.

          For Wix Stores, pass `null` or omit this field, as each store has only one category tree.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="returnNonVisibleCategories" type="boolean">

      Whether to return non-visible categories.

      Default: `false` (only visible categories are returned)

    </ParamField>

    <ParamField body="fields" type="string[]">

      Fields to include in the response.

      Constraints: `maxItems 100`.

      **Supported values:**

      - `BREADCRUMBS_INFO`
      - `DESCRIPTION`
      - `RICH_CONTENT_DESCRIPTION`

    </ParamField>

    ## Response Object

    <ResponseField name="categories" type="Category[]">

      List of categories.

      Constraints: `minItems 0`, `maxItems 1000`.

      See the [Category Object](/api-reference/business-solutions/stores/catalog-v3/categories/category-object) for this object's fields.

    </ResponseField>

    <ResponseField name="pagingMetadata" type="CursorPagingMetadata">

      Paging metadata.

      <Expandable title="pagingMetadata properties">

        <ResponseField name="count" type="integer">

          Number of items returned in the response.

        </ResponseField>

        <ResponseField name="cursors" type="Cursors">

          Cursor strings that point to the next page, previous page, or both.

          <Expandable title="cursors properties">

            <ResponseField name="next" type="string">

              Cursor string pointing to the next page in the list of results.

            </ResponseField>

            <ResponseField name="prev" type="string">

              Cursor pointing to the previous page in the list of results.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="hasNext" type="boolean">

          Whether there are more pages to retrieve following the current page.

          + `true`: Another page of results can be retrieved.
          + `false`: This is the last page.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <Note>

      This method doesn't return any custom errors, but may return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).
