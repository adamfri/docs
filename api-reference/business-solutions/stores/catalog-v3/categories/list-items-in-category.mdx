    <div className="wix-ref">

    Retrieves a list of up to 100 items from a category.

    By default, items are sorted by the date they were added to the category, newest first. To use the category's manual arrangement instead, pass `useCategoryArrangement: true`.
    When `useCategoryArrangement` is `true`, items arranged with [Set Arranged Items](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/categories/set-arranged-items) appear first in their specified order, followed by remaining items sorted by date added.

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.CATEGORIES.CATEGORY_READ">Read categories</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`, `MEMBER`, `VISITOR`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/categories/v1/categories/{categoryId}/list-items
    ```

    ## Path Params

    <ParamField path="categoryId" type="string" required>

      Category ID.

    </ParamField>

    ## Body Params

    <ParamField body="treeReference" type="TreeReference" required>

      Category tree reference details.

      <Expandable title="treeReference properties">

        <ParamField body="appNamespace" type="string" required>

          Namespace of the app whose catalog this category tree belongs to.

          Currently, only `"@wix/stores"` is supported.

          Constraints: `minLength 4`, `maxLength 150`.

        </ParamField>

        <ParamField body="treeKey" type="string">

          Key to differentiate between multiple trees managed by the same app.

          For Wix Stores, pass `null` or omit this field, as each store has only one category tree.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="useCategoryArrangement" type="boolean">

      Whether to use the category's manual arrangement for sorting items.

      When `true`, manually arranged items appear first in their specified order, followed by remaining items sorted by date added (newest first).
      When `false`, all items are sorted by date added (newest first).

      Default: `false`

    </ParamField>

    <ParamField body="includeItemsFromSubcategories" type="boolean">

      Whether to include items from subcategories.

      Default: `false`

    </ParamField>

    ## Response Object

    <ResponseField name="items" type="ItemReference[]">

      List of items in the category.

      Constraints: `maxItems 100`.

      <Expandable title="items properties">

        <ResponseField name="catalogItemId" type="string">

          ID of the item within the catalog.

          For Wix Stores, this is the product ID from the [Catalog V3 Products API](https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/products-v3/introduction).

          Constraints: `minLength 1`, `maxLength 36`.

        </ResponseField>

        <ResponseField name="appId" type="string">

          ID of the Wix app providing the catalog.

          Currently, only Wix Stores is supported. Use `"215238eb-22a5-4c36-9e7b-e7c08025e04e"` for all Wix Stores products.

          Constraints: `minLength 1`, `maxLength 36`.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="pagingMetadata" type="PagingMetadataV2">

      Paging metadata.

      <Expandable title="pagingMetadata properties">

        <ResponseField name="count" type="integer">

          Number of items returned in the response.

        </ResponseField>

        <ResponseField name="offset" type="integer">

          Offset that was requested.

        </ResponseField>

        <ResponseField name="total" type="integer">

          Total number of items that match the query. Returned if offset paging is used and the `tooManyToCount` flag is not set.

        </ResponseField>

        <ResponseField name="cursors" type="Cursors">

          Cursors to navigate through the result pages using `next` and `prev`. Returned if cursor paging is used.

          <Expandable title="cursors properties">

            <ResponseField name="next" type="string">

              Cursor string pointing to the next page in the list of results.

            </ResponseField>

            <ResponseField name="prev" type="string">

              Cursor pointing to the previous page in the list of results.

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Errors

    <Note>

      This method doesn't return any custom errors, but may return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
