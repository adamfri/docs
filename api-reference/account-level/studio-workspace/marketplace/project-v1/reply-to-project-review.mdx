    Adds the provider's reply to the client's review of a completed project.

    Each time the project is updated, `revision` increments by 1. The current `revision` must be passed when updating the project. This ensures you're working with the latest project and prevents unintended overwrites.

    The project's `status` must be `COMPLETED`, and the project must have a `review` that doesn't
    already have a `reply`. A review supports a single reply, so a reply can't be changed or removed
    once submitted.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix user or by using an account level API key.

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.ARENA.MANAGE-LEADS">Manage CRM and Marketplace</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    <Note>This is an account-level method.</Note>

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/partners/marketplace/v1/projects/{projectId}/reply-to-review
    ```

    ## Path Params

    <ParamField path="projectId" type="string" required>

      ID of the project whose review to reply to.

    </ParamField>

    ## Body Params

    <ParamField body="revision" type="integer" required>

      Revision number, which increments by 1 each time the project is updated. To prevent conflicting
      changes, the current revision must be passed.

    </ParamField>

    <ParamField body="reply" type="Reply" required>

      Provider's reply to the client's review.

        </ParamField>

        <ParamField body="date" type="datetime">

          Date and time the reply was submitted.

        </ParamField>

      </Expandable>

    </ParamField>
