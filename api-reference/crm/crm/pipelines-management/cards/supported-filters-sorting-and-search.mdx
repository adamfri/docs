This article covers field support for filtering, sorting, and searching
in the Cards API.

## Overview

The Cards API includes three endpoints for querying and searching cards:

- [**Query Cards**](fallback::https://dev.wix.com/docs/api-reference/crm/crm/pipelines-management/cards/query-cards) for basic querying with filters and sorting.
- [**Search Cards**](fallback::https://dev.wix.com/docs/api-reference/crm/crm/pipelines-management/cards/search-cards) for enhanced searching with full-text search, filters, and sorting.
- [**Search Cards by Stage**](fallback::https://dev.wix.com/docs/api-reference/crm/crm/pipelines-management/cards/search-cards-by-stage) for searching cards within specific pipeline stages.

<Note>

The filterable, sortable, and searchable fields differ between the Query and Search endpoints.
Search endpoints offer more comprehensive filtering and sorting capabilities.

</Note>

## Query Cards

The table below shows field support for filters and sorting for the card object:

| Field                   | Supported Filters                          | Sortable |
|-------------------------|--------------------------------------------|----------|
| `id`                    | `$eq`, `$ne`, `$in`, `$nin`                |          |
| `pipelineId`            | `$eq`, `$ne`, `$in`, `$nin`                |          |
| `stageId`               | `$eq`, `$ne`, `$in`, `$nin`                |          |
| `createdDate`           | `$eq`, `$ne`, `$gt`, `$lt`, `$gte`, `$lte` | Sortable |
| `updatedDate`           | `$eq`, `$ne`, `$gt`, `$lt`, `$gte`, `$lte` | Sortable |

### Supported Aggregation Types

| Type             | Description                                                                                 |
|------------------|---------------------------------------------------------------------------------------------|
| `SCALAR`         | Calculates single numerical values such as card totals, min, or max values.                 |
| `VALUE`          | Groups by field values and counts occurrences, such as cards by priority or cards by stage. |
| `RANGE`          | Groups values by defined ranges.                                                            |
| `DATE_HISTOGRAM` | Groups by time intervals, such as cards created per week or month.                          |

## Search Cards by Stage Endpoint

The **Search Cards by Stage** endpoint (`/v1/cards/search-by-stage`) allows you to search for cards within specific pipeline stages. This endpoint:

- Requires `pipelineId` and `stageIds` parameters
- Uses the same enhanced search capabilities as the Search Cards endpoint
- Returns results grouped by stage
- Supports the same filtering, sorting, and search fields as the Search Cards endpoint

### Usage

```json
{
  "pipelineId": "f9e8d7c6-b5a4-3210-fedc-ba9876543210",
  "stageIds": [
    "01234567-89ab-cdef-0123-456789abcdef",
    "89abcdef-0123-4567-89ab-cdef01234567"
  ],
  "search": {
    "expression": "enterprise software",
    "filter": {
      "value.value": { "$gte": "100000.00" },
      "assigneeId": { "$exists": true }
    },
    "sort": [
      { "fieldName": "value.value", "order": "DESC" }
    ],
    "paging": {
      "limit": 25,
      "offset": 0
    }
  },
  "nameFormat": "BY_FIRST_NAME"
}
```

## Additional Features

### Name Format

Both Search Cards and Search Cards by Stage endpoints support a `nameFormat` parameter that controls how contact names are handled:

- `BY_FIRST_NAME` (default) - Orders and matches by first name, then last name
- `BY_LAST_NAME` - Orders and matches by last name, then first name

This affects sorting by `mainContact.displayName` and searching by `mainContact.fullName` or `additionalContacts.fullName`.

## Aggregations (Search Endpoints Only)

Aggregations allow you to group and summarize card data. They are only available in Search Cards and Search Cards by Stage endpoints, not in the basic Query Cards endpoint.

### Supported Aggregation Types

| Type             | Description                                   | Use Case                                 |
|------------------|-----------------------------------------------|------------------------------------------|
| `SCALAR`         | Calculates single numerical values            | Total/min/max deal value, contact counts |
| `VALUE`          | Groups by field values and counts occurrences | Cards by priority, cards by stage        |
| `RANGE`          | Groups values into defined ranges             | Deal value ranges, cards by month        |
| `DATE_HISTOGRAM` | Groups by time intervals                      | Cards created per week/month             |

### Aggregation Configuration

- **SCALAR aggregations**: Support `MIN`, `MAX`, `SUM`, and `COUNT_DISTINCT` operations.
- **VALUE aggregations**: Can return up to 250 results per aggregation (default limit is 10).
- **RANGE aggregations**: Support up to 50 buckets per aggregation.
- **Maximum aggregations**: Up to 10 aggregations per search request.
