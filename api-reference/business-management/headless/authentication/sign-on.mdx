    Authenticates a member without credentials and returns a session token.

    This method provides authentication that automatically creates or updates
    member accounts as needed during the authentication process.
    Use this only for trusted integrations and scenarios where you already have verified user information.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.DC-IDENTITY.MANAGE_AUTHENTICATION">Manage Members Authentication</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/iam/authentication/v2/sign-on
    ```

              **Supported values:**

              - `UNKNOWN_STATUS` — Unknown status. This value isn't used.
              - `PENDING` — Identity is pending verification, owner approval, or both.
              - `ACTIVE` — Identity is active and can log in.
              - `DELETED` — Identity is deleted. This identity can't log in.
              - `BLOCKED` — Identity is blocked. This identity can't log in.
              - `OFFLINE` — Identity is offline. This identity can't log in.

            </ResponseField>

            <ResponseField name="reasons" type="string[]">

              Reasons for the current identity status.

              **Supported values:**

              - `UNKNOWN_REASON` — Unknown reason. This value isn't used.
              - `PENDING_ADMIN_APPROVAL_REQUIRED` — The identity is waiting for admin approval. After the approval, the identity has an `ACTIVE` status.
              - `PENDING_EMAIL_VERIFICATION_REQUIRED` — The identity has to verify the email. After the verification, the identity has an `ACTIVE` status.
              - `PENDING_REQUIRED_FIELDS_MISSING` — The identity is missing fields that are marked as required on the site's signup form. After completing them, the identity has an `ACTIVE` status.

              - `CALL` — Requires a code sent by phone call.
              - `EMAIL` — Requires a code sent by email.
              - `TOTP` — Requires authentication via an authenticator app.
              - `PUSH` — Requires authentication via a push notification.
              - `WEBAUTHN` — Requires authentication via WebAuthn/passkey.
              - `RECOVERY_CODE` — Requires a recovery code.

            </ResponseField>

              Factor status.

              **Supported values:**

              - `INACTIVE` — Factor requires activation.
              - `ACTIVE` — Factor is active and can be used for authentication.
