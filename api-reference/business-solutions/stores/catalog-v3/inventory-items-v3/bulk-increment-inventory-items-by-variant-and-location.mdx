    <div className="wix-ref">

    Increments quantities of multiple inventory items by variant and location.

    <Note>

    `trackQuantity` must be `true` to allow for incrementing the quantity.

    </Note>

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.STORES.INVENTORY_ITEM_WRITE">Inventory write in v3 catalog</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/stores/v3/bulk/inventory-items/increment-by-variant-and-location
    ```

    ## Body Params

    <ParamField body="incrementData" type="IncrementDataByVariantAndLocation[]" required>

      Variant and location IDs, as well as increment data.

      Constraints: `minItems 1`, `maxItems 300`.

      <Expandable title="incrementData properties">

        <ParamField body="variantId" type="string" required>

          Variant ID.

          Constraints: `format GUID`.

        </ParamField>

        <ParamField body="locationId" type="string">

          Location ID.

        </ParamField>

        <ParamField body="incrementBy" type="integer" required>

          Amount to increment by.

          Constraints: `min 1`, `max 99999`.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="returnEntity" type="boolean">

      Whether to return the full inventory item entities in the response.

      Default: `false`

    </ParamField>

    <ParamField body="reason" type="string">

      Reason for increment inventory action.

      **Supported values:**

      - `ORDER`
      - `MANUAL`
      - `REVERT_INVENTORY_CHANGE`

    </ParamField>

    ## Response Object

    <ResponseField name="results" type="BulkInventoryItemResult[]">

      Inventory items updated by bulk action.

      Constraints: `minItems 1`, `maxItems 300`.

      <Expandable title="results properties">

        <ResponseField name="itemMetadata" type="ItemMetadata">

          Bulk action metadata for inventory item.

          <Expandable title="itemMetadata properties">

            <ResponseField name="id" type="string">

              Item ID. Should always be available, unless it's impossible (for example, when failing to create an item).

            </ResponseField>

            <ResponseField name="originalIndex" type="integer">

              Index of the item within the request array. Allows for correlation between request and response items.

            </ResponseField>

            <ResponseField name="success" type="boolean">

              Whether the requested action was successful for this item. When `false`, the `error` field is populated.

            </ResponseField>

            <ResponseField name="error" type="ApplicationError">

              Details about the error in case of failure.

              _Nested structure omitted for brevity — see the `ApplicationError` object._

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="item" type="InventoryItem">

          Full inventory item entity.

          Returned only if `returnEntity: true` is passed in the request.

          See the [Inventory Item Object](/api-reference/business-solutions/stores/catalog-v3/inventory-items-v3/inventory-item-object) for this object's fields.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="bulkActionMetadata" type="BulkActionMetadata">

      Bulk action metadata details as: totalSuccess and totalFailure.

      <Expandable title="bulkActionMetadata properties">

        <ResponseField name="totalSuccesses" type="integer">

          Number of items that were successfully processed.

        </ResponseField>

        <ResponseField name="totalFailures" type="integer">

          Number of items that couldn't be processed.

        </ResponseField>

        <ResponseField name="undetailedFailures" type="integer">

          Number of failures without details because detailed failure threshold was exceeded.

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `428` | `FAILED_PRECONDITION` | `INVENTORY_QUANTITY_NOT_TRACKED` | Increment attempted for untracked inventory. Enable inventory tracking first. |
    | `428` | `FAILED_PRECONDITION` | `MAX_QUANTITY_LIMIT_REACHED` | Increment would exceed the maximum quantity limit. |
    | `428` | `FAILED_PRECONDITION` | `NOT_FOUND` | Inventory item with the specified `variant_id` and `location_id` not found. |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
