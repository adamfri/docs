A product provided by a business partner and displayed in the Wix Marketplace.

Products can be of type DROPSHIPPING, WHOLESALE, or both.
Wix users can discover and add these products to their stores.

    <ResponseField name="types" type="string[]">

      Business model types this product supports.

      Constraints: `minItems 1`, `maxItems 2`.

      **Supported values:**

      - `DROPSHIPPING` — Product is fulfilled by the supplier without inventory management by the store owner.
      - `WHOLESALE` — Product is sold in bulk quantities with tiered pricing.
      - `PRINT_ON_DEMAND` — Product is manufactured after purchase; no pre‑held inventory.

    </ResponseField>

    <ResponseField name="options" type="ProductOption[]">

      Product options that customers can choose from.

      Options display available product variations like size and color to help buyers make purchase decisions.
      Currently, options are informational only and don't create separate inventory items or variants.

      There are 2 predefined option types you can use:
      - `color`: Color choices for the product. Values should be standard color names. For example, `"Black"`, `"White"`, `"Yellow"`.
      - `size`: Size choices for the product. Values should be standard size labels. For example, `"S"`, `"M"`, `"L"`, `"XL"`.

      Constraints: `maxItems 6`.

      <Expandable title="options properties">

        <ResponseField name="name" type="string">

          Option name.

          There are 2 predefined options you can use:
          - `color`: Represents color choices for the product. Values should be standard color names. For example, `"Black"`, `"White"`, `"Yellow"`.
          - `size`: Represents size choices for the product. Values should be standard size labels. For example, `"S"`, `"M"`, `"L"`, `"XL"`.

          Constraints: `minLength 1`, `maxLength 50`.

        </ResponseField>

        <ResponseField name="description" type="string">

          Optional description explaining the option.

        </ResponseField>

        <ResponseField name="values" type="OptionValue[]">

          Available values for this option.

          All values within a single option must be the same type. For example, an option can't mix `color` values with `text` values.

          Constraints: `maxItems 100`.

        </ResponseField>

      </Expandable>

    <ResponseField name="inventory" type="Inventory">

      Current inventory information including stock level tier, calculated as the sum of all variant quantities.

      Providers update inventory by calling [Update Product](https://dev.wix.com/docs/api-reference/business-solutions/suppliers-hub/products/update-product) with the new `quantity`. The `tier` is computed automatically and changes to the tier trigger a Product Updated webhook with `inventory.tier` in the modified fields.

      <Expandable title="inventory properties">

        <ResponseField name="tier" type="string">

          Abstracted inventory level, calculated from `quantity`.

          When `quantity` is null, the tier is `UNKNOWN_INVENTORY_TIER`, indicating inventory hasn't been reported yet.

          **Read-only.**

          **Supported values:**

          - `EMPTY` — No inventory available (0 items).
          - `LOW` — Low inventory level (11 to 25 items).
          - `MEDIUM` — Medium inventory level (26 to 50 items).
          - `HIGH` — High inventory level (51 to 100 items).
          - `VERY_LOW` — Very low inventory level (1 to 10 items).
          - `VERY_HIGH` — Very high inventory level (101+ items).

        </ResponseField>

        <ResponseField name="quantity" type="integer">

          Exact inventory quantity across all variants.

          When null, inventory hasn't been reported yet. A value of `0` means out of stock.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="directCategories" type="ProductCategory[]">

      List of categories that directly contain this product.

      Each category's namespace must match at least one of the product's types.
      For example, if a product has type `DROPSHIPPING`, its categories must use `DROPSHIPPING_NAMESPACE`.
      Products with both `DROPSHIPPING` and `WHOLESALE` types can have categories from both namespaces.

      Constraints: `maxItems 50`.

      <Expandable title="directCategories properties">

        <ResponseField name="id" type="string">

          Category ID.

          Constraints: `format GUID`.

        </ResponseField>

        <ResponseField name="index" type="integer">

          Product's position within this category.

          **Read-only.**

        </ResponseField>

        <ResponseField name="namespace" type="string">

          The namespace of the category tree this assignment belongs to.

          **Supported values:**

          - `DROPSHIPPING_NAMESPACE` — Namespace for the dropshipping category tree.
          - `WHOLESALE_NAMESPACE` — Namespace for the wholesale category tree.
          - `PRINT_ON_DEMAND_NAMESPACE` — Namespace for the print on demand category tree.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="wholesaleOptions" type="WholesaleOptions">

      Wholesale-specific configuration including tiered pricing and minimum order quantities.

      Required when `types` includes `WHOLESALE`.

      <Expandable title="wholesaleOptions properties">

        <ResponseField name="priceTiers" type="PriceTier[]">

          Tiered pricing based on order quantity ranges.

          Price tiers must be continuous with no gaps in quantity ranges.
          For example, if tier 1 covers quantities 1-100, tier 2 must start at 101.
          The system validates tier continuity when creating or updating products.

          Constraints: `maxItems 5`.

          <Expandable title="priceTiers properties">

            <ResponseField name="priceFrom" type="string">

              Minimum price for this quantity tier in USD.

              If `priceTo` isn't specified, this price applies to all quantities in the tier.

              Constraints: `>= 0`, `<= 999999999`.

            </ResponseField>

            <ResponseField name="priceTo" type="string">

              Maximum price for this quantity tier in USD.

              Optional for fixed-price tiers.

            </ResponseField>

            <ResponseField name="countFrom" type="integer">

              Minimum quantity for this price tier, inclusive.

            </ResponseField>

            <ResponseField name="countTo" type="integer">

              Maximum quantity for this price tier, inclusive.

              If not specified, this tier applies to all quantities greater or equal to `countFrom`.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="minimumOrderQuantity" type="integer">

          Minimum quantity required for wholesale orders.

        </ResponseField>

      </Expandable>

      Required when `types` include `PRINT_ON_DEMAND`.

      <Expandable title="printOnDemandOptions properties">

        <ResponseField name="printTechnologies" type="string[]">

          Set of possible print technologies for the Product

          Constraints: `minItems 1`, `maxItems 3`.

          **Supported values:**

          - `DIRECT_TO_FILM` — Transfers printed on film and heat-pressed onto fabric.
          - `DIRECT_TO_GARMENT` — Ink directly onto garment.
          - `CUT_SEW_SUBLIMATION` — Panels are printed first, then sewn. All‑over coverage with precise placements.
          - `DIGITAL_PRINTING` — Non‑DTG digital methods (e.g., roll‑to‑roll).
          - `EMBROIDERY` — Stitched threads, premium look.
          - `SUBLIMATION` — Dye infused into polyester/poly‑coated substrates.
          - `UV_PRINTING` — Cures ink with UV light on rigid or treated surfaces.
          - `KNITWEAR` — Pattern/design is knitted, not printed.
          - `DIRECT_TO_FABRIC` — Designs are printed directly onto rolls of fabric, which are then cut and sewn into the final product.

        </ResponseField>
