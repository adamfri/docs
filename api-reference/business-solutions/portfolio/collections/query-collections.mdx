    Retrieves a list of collections given the provided paging, filtering, and sorting. Up to 100 collections can be returned per request.

    The default `sort` is `id` in `ASC`.

    To learn how to query collections, see [API Query Language](https://dev.wix.com/docs/rest/articles/getting-started/api-query-language).

    | Property | Filters | Sort |
    | --- | --- | --- |
    | `id` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `title` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `description` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `slug` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `sortOrder` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte` | Sort: `ASC`, `DESC` |
    | `hidden` | `$eq`, `$ne`, `$in`, `$exists` | None |
    | `createdDate` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte` | Sort: `ASC`, `DESC` |
    | `updatedDate` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte` | Sort: `ASC`, `DESC` |

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.PORTFOLIO.MANAGE-PORTFOLIO">Manage Portfolio</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `MEMBER`, `APP`, `VISITOR`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/portfolio/v1/collections/query
    ```

    ## Body Params

    <ParamField body="query" type="QueryV2" required>

      Query options.

      <Expandable title="query properties">

        <ParamField body="filter" type="object">

          Filter object.

          Learn more about [filtering](https://dev.wix.com/docs/rest/articles/getting-started/api-query-language#filters).

        </ParamField>

        <ParamField body="sort" type="Sorting[]">

          Sort object.

          Learn more about [sorting](https://dev.wix.com/docs/rest/articles/getting-started/api-query-language#sorting).

          <Expandable title="sort properties">

            <ParamField body="fieldName" type="string">

              Name of the field to sort by.

              Constraints: `maxLength 512`.

            </ParamField>

            <ParamField body="order" type="string">

              Sort order.

              **Supported values:**

              - `ASC`
              - `DESC`

            </ParamField>

            <ParamField body="origin" type="AddressLocation">

              Origin point for geo-distance sorting on a GEO field
              results are ordered by distance from this point (ASC = nearest first, DESC = farthest first).

              _Nested structure omitted for brevity — see the `AddressLocation` object._

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField body="fields" type="string[]">

          Array of projected fields. A list of specific field names to return. If `fieldsets` are also specified, the union of `fieldsets` and `fields` is returned.

        </ParamField>

        <ParamField body="fieldsets" type="string[]">

          Array of named, predefined sets of projected fields. A array of predefined named sets of fields to be returned. Specifying multiple `fieldsets` will return the union of fields from all sets. If `fields` are also specified, the union of `fieldsets` and `fields` is returned.

        </ParamField>

      </Expandable>

      <Expandable title="One of the following">

        <ParamField body="pagingMethod" type="pagingMethod">

          pagingMethod

          <Expandable title="pagingMethod properties">

            <ParamField body="cursorPaging" type="CursorPaging">

              Cursor token pointing to a page of results. Not used in the first request. Following requests use the cursor token and not `filter` or `sort`.

              _Nested structure omitted for brevity — see the `CursorPaging` object._

            </ParamField>

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="includePageUrl" type="boolean">

      Whether to include the collection's page URL and relative path in the response. Default: `false`

    </ParamField>

    ## Response Object

    <ResponseField name="collections" type="Collection[]">

      List of collections.

      See the [Collection Object](/api-reference/business-solutions/portfolio/collections/collection-object) for this object's fields.

    <ResponseField name="metadata" type="PagingMetadataV2">

      <Expandable title="metadata properties">

          Number of items returned in the response.

        <ResponseField name="offset" type="integer">

          Offset that was requested.

          Total number of items that match the query. Returned if offset paging is used and the `tooManyToCount` flag is not set.

          Flag that indicates the server failed to calculate the `total` field.

        </ResponseField>

        <ResponseField name="cursors" type="Cursors">

          Cursors to navigate through the result pages using `next` and `prev`. Returned if cursor paging is used.

          <Expandable title="cursors properties">

            <ResponseField name="next" type="string">

              Cursor string pointing to the next page in the list of results.

            </ResponseField>

            <ResponseField name="prev" type="string">

              Cursor pointing to the previous page in the list of results.

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>
