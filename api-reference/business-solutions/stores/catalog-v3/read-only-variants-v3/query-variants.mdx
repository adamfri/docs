    Retrieve product variants using structured queries with cursor-based pagination.

    Use this endpoint for simple filtering operations on `productData.productId` and variant identifiers.
    The `id` field is deprecated and is not globally unique by itself. Use `productData.productId`
    together with `variantId` as the unique variant key.
    For complex queries with free-text search and aggregations, use Search Variants instead.

    Up to 1,000 variants can be returned per request.

    To learn about working with _Query_ endpoints, see
    [API Query Language](https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/data-retrieval/about-the-wix-api-query-language),
    and [Sorting and Paging](https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/data-retrieval/about-sorting-and-paging).

    Learn more about the differences between [_Query_ and _Search_](https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/data-retrieval/about-search-query-and-list-methods) methods.

    | Property | Filters | Sort |
    | --- | --- | --- |
    | `id` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `variantId` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |
    | `productData.productId` | `$eq`, `$ne`, `$in`, `$exists`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` | Sort: `ASC`, `DESC` |

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.STORES.PRODUCT_READ">Read products in v3 catalog</span>
    <span className="wix-scope" title="SCOPE.STORES.PRODUCT_READ_ADMIN">Product v3 read admin</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`, `MEMBER`, `VISITOR`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/stores/v3/products/query-variants
    ```

    ## Body Params

    <ParamField body="query" type="CursorQuery">

      WQL expression for filtering variants.

      <Expandable title="query properties">

        <ParamField body="filter" type="object">

          Filter object in the following format:
          `"filter" : {`
          "fieldName1": "value1",
          "fieldName2":&#123;"$operator":"value2"&#125;
          &#125;``
          Example of operators: `$eq`, `$ne`, `$lt`, `$lte`, `$gt`, `$gte`, `$in`, `$hasSome`, `$hasAll`, `$startsWith`, `$contains`

        </ParamField>

        <ParamField body="sort" type="Sorting[]">

          Sort object in the following format:
          `[{"fieldName":"sortField1","order":"ASC"},{"fieldName":"sortField2","order":"DESC"}]`

          Constraints: `maxItems 5`.

          <Expandable title="sort properties">

            <ParamField body="fieldName" type="string">

              Name of the field to sort by.

              Constraints: `maxLength 512`.

            </ParamField>

            <ParamField body="order" type="string">

              Sort order.

              **Supported values:**

              - `ASC`
              - `DESC`

            </ParamField>

          </Expandable>

        </ParamField>

      </Expandable>

      <Expandable title="One of the following">

        <ParamField body="pagingMethod" type="pagingMethod">

          pagingMethod

          <Expandable title="pagingMethod properties">

            <ParamField body="cursorPaging" type="CursorPaging">

              Cursor token pointing to a page of results. Not used in the first request. Following requests use the cursor token and not `filter` or `sort`.

              _Nested structure omitted for brevity — see the `CursorPaging` object._

            </ParamField>

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="fields" type="string[]">

      List of additional fields to include in the response.
      See VariantOps.RequestedFields for available options.

      Constraints: `maxItems 100`.

      **Supported values:**

      - `CURRENCY` — Include currency information in product data.

      Returns the currency code (ISO-4217 format) used for pricing this variant.
      Defaults to the site's currency unless specified in request headers.
      - `MERCHANT_DATA` — Include merchant-specific data such as cost and profit information.

      Returns revenue details including cost, profit, and profit margin.
      Requires `SCOPE.STORES.PRODUCT_READ_ADMIN` permission scope.
      - `SUBSCRIPTION_PRICES_INFO` — Include subscription pricing information.

      Returns calculated prices for different subscription plans with applied discounts.
      Only relevant for variants that are part of subscription offerings.
      - `WEIGHT_MEASUREMENT_UNIT_INFO` — Include weight measurement unit information.

      Returns the weight measurement unit (kg, lb, etc.) used for the variant.
      Useful for shipping calculations and product comparisons.

    </ParamField>

    ## Response Object

    <ResponseField name="variants" type="ReadOnlyVariant[]">

      Variants matching the query criteria.

      See the [Read Only Variant Object](/api-reference/business-solutions/stores/catalog-v3/read-only-variants-v3/read-only-variant-object) for this object's fields.

    </ResponseField>

    <ResponseField name="pagingMetadata" type="CursorPagingMetadata">

      <Expandable title="pagingMetadata properties">

          Number of items returned in the response.

        </ResponseField>

        <ResponseField name="cursors" type="Cursors">

          Cursor strings that point to the next page, previous page, or both.

          <Expandable title="cursors properties">

            <ResponseField name="next" type="string">

              Cursor string pointing to the next page in the list of results.

            </ResponseField>

            <ResponseField name="prev" type="string">

              Cursor pointing to the previous page in the list of results.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="hasNext" type="boolean">

          Whether there are more pages to retrieve following the current page.

          + `true`: Another page of results can be retrieved.
          + `false`: This is the last page.

        </ResponseField>

      </Expandable>

    </ResponseField>
