    Starts verifying a location with Google.

    Call Get Verification Options first to find out which methods Google allows for
    the location, then specify one here.

    For `ADDRESS`, `EMAIL`, `PHONE_CALL` and `SMS`, Google sends a PIN to the site
    owner. Pass it to Complete Verification to finish.

    For `AUTO`, Google verifies the location itself. There's no PIN and no second
    call, and `verificationState` comes back as `VERIFIED` straight away.

    `VERIFIED` is narrower than it sounds. It means the location has business
    authority and has entered Google's quality review. It does not mean the profile
    is live and trusted: for that, check `hasVoiceOfMerchant` with Get Voice Of
    Merchant. A location can be verified and still not be publicly visible.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    ## Endpoint

    ```http
    POST https://www.wixapis.com/gbp/v1/locations/{locationId}:startVerification
    ```

    ## Path Params

    <ParamField path="locationId" type="string" required>

      Location ID. This is Google's location identifier.

    </ParamField>

    ## Body Params

    <ParamField body="method" type="string" required>

      Verification method chosen by the merchant.

      **Supported values:**

      - `ADDRESS` — Postcard to the business address
      - `EMAIL` — Email with a PIN
      - `PHONE_CALL` — Automated phone call with a PIN
      - `SMS` — SMS with a PIN
      - `AUTO` — Google-side instant verification (e.g. domain ownership)

    </ParamField>

    <ParamField body="methodInput" type="string">

      Input the chosen method needs. Defaults come from the matching
      GetVerificationOptions option:
      - EMAIL: full address `user@domain`. May differ from `email_data` only
      when `email_data.user_name_editable` is true.
      - PHONE_CALL / SMS: the phone number; normally `phone_number` as returned.
      - ADDRESS: recipient contact name printed on the postcard (optional).

      Constraints: `maxLength 255`.

    </ParamField>

    ## Response Object

    <ResponseField name="pendingVerificationId" type="string">

      Opaque ID for this verification.

      For a PIN-based method, pass this back to Complete Verification.

      It's also set for automatic verification, which has no PIN and no Complete
      Verification step. So its presence doesn't tell you whether there's more to
      do: branch on `verificationState` instead, where `VERIFIED` means the flow
      is already finished.

      Constraints: `maxLength 255`.

    </ResponseField>

    <ResponseField name="verificationState" type="string">

      Verification state after starting the process.

      **Supported values:**

      - `UNVERIFIED`
      - `PENDING_VERIFICATION`
      - `VERIFIED`

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `428` | `FAILED_PRECONDITION` | `UNSUPPORTED_VERIFICATION_METHOD` | Raised for a method that has no Google counterpart at all (VERIFICATION_METHOD_UNKNOWN). AUTO is NOT one of them any more — see the AUTO_VERIFICATION_NOT_ELIGIBLE error below. |
    | `428` | `FAILED_PRECONDITION` | `AUTO_VERIFICATION_NOT_ELIGIBLE` | Google advertised AUTO for this location via GetVerificationOptions and then refused it ("Location is not eligible for the AUTO method"). Typed separately from GOOGLE_API_CALL_FAILED so the caller can offer another method rather than a retry that will always fail (WIXSEO-4775). |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
