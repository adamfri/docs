    Resolves SEO tags for a static page using its page name and optional SEO data parameters.

    This method is optimized for static pages and supports SEO data parameters to customize
    the generated tags. It returns page-specific SEO tags that include standard meta tags
    and structured data appropriate for static content.

    When `seoData` or `pageName` is omitted, this method resolves the page matching `pageUrl` in the
    site structure and derives the missing value from it; a value supplied on the request takes
    precedence. That per-page lookup covers Vibe/Wix-managed-headless pages only — classic Wix Editor
    and Wix Studio pages have no entry in it, so their stored per-page SEO configuration is not read
    back and only site-level defaults and patterns apply. Pass `seoData` explicitly to resolve against
    a known set of tags.

    Note: the response's `Tag.custom` field does not indicate whether a standard tag (title,
    description, etc.) came from a manual per-page override; it only flags entries from the site's
    separate Advanced/Custom Tags list. Use the returned `Tag.children`/`props` content itself, not
    `custom`, to inspect the resolved tags.

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.PROMOTE.VIEW-SEO">View SEO Settings</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `MEMBER`, `APP`, `VISITOR`.

    ## Endpoint

    ```http
    GET https://www.wixapis.com/promote/seo/v1/resolve-static-page-seo-tags
    ```

    ## Query Params

    <ParamField query="pageUrl" type="string">

      Full canonical URL of the static page where the SEO tags are applied.

      Constraints: `format WEB_URL`, `minLength 1`, `maxLength 2048`.

    </ParamField>

    <ParamField query="pageName" type="string">

      Optional page name, used as the title/pattern fallback. When omitted (e.g.
      headless/Vibe callers that only have the URL), it is derived from the matching
      page in the site structure.

      Constraints: `maxLength 255`.

    </ParamField>

    <ParamField query="seoData" type="SeoSchema">

      Custom SEO data for the static page

      <Expandable title="seoData properties">

        <ParamField query="tags" type="Tag[]">

          SEO tag information.

          <Expandable title="tags properties">

            <ParamField query="type" type="string">

              SEO tag type.

              Supported values: `title`, `meta`, `script`, `link`.

            </ParamField>

            <ParamField query="props" type="object">

              A `{"key": "value"}` pair object where each SEO tag property (`"name"`, `"content"`, `"rel"`, `"href"`) contains a value.
              For example: `{"name": "description", "content": "the description itself"}`.

            </ParamField>

            <ParamField query="meta" type="object">

              SEO tag metadata. For example, `{"height": 300, "width": 240}`.

            </ParamField>

            <ParamField query="children" type="string">

              SEO tag inner content. For example, `<title> inner content </title>`.

            </ParamField>

            <ParamField query="custom" type="boolean">

              Whether the tag is a [custom tag](https://support.wix.com/en/article/adding-additional-meta-tags-to-your-sites-pages) —
              i.e. an entry from the site's Advanced/Custom Tags list.

              This flag is scoped to that feature only. It is NOT an indicator of whether a standard tag
              (`title`, `description`, Open Graph, etc.) reflects a manually configured value versus a computed
              default/pattern — standard tags always resolve with `custom: false`, even when their content comes
              from a page's manually saved SEO title/description override. Don't use this field to verify whether
              a live page reflects a manual per-page SEO edit.

              Limitation: when `ResolveStaticPageSeoTags` is called without `seoData`, the per-page SEO data is read
              only from the Vibe/Wix-managed-headless override store. That store holds nothing for classic Wix Editor
              or Wix Studio pages, so even genuine Advanced/Custom Tags saved on those pages are missing from the
              response entirely — there, `false` means this API could not tell, not that no custom tag exists.
              Pass `seoData` explicitly to resolve against a known set of tags.

            </ParamField>

            <ParamField query="disabled" type="boolean">

              Whether the tag is disabled. If the tag is disabled, people can't find your page when searching for this phrase in search engines.

            </ParamField>

          </Expandable>

        </ParamField>

        <ParamField query="settings" type="Settings">

          SEO general settings.

          <Expandable title="settings properties">

            <ParamField query="preventAutoRedirect" type="boolean">

              Whether the [automatical redirect visits](https://support.wix.com/en/article/customizing-your-pages-seo-settings-in-the-seo-panel) from the old URL to the new one is enabled.

              Default: `false` (automatical redirect is enabled).

            </ParamField>

            <ParamField query="keywords" type="Keyword[]">

              User-selected keyword terms for a specific page.

              Constraints: `maxItems 5`.

              <Expandable title="keywords properties">

                <ParamField query="term" type="string">

                  Keyword value.

                </ParamField>

                <ParamField query="isMain" type="boolean">

                  Whether the keyword is the main focus keyword.

                </ParamField>

                <ParamField query="origin" type="string">

                  The source that added the keyword terms to the SEO settings.

                </ParamField>

              </Expandable>

            </ParamField>

          </Expandable>

        </ParamField>

      </Expandable>

    </ParamField>

    ## Response Object

    <ResponseField name="seoTags" type="SeoTags">

      The resolved SEO tags entity containing static page-specific metadata.

      See the [Seo Tags Object](/api-reference/site/viewer/seo-tags/seo-tags-object) for this object's fields.

    </ResponseField>

    ## Errors

    <Note>

      This method doesn't return any custom errors, but may return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>
