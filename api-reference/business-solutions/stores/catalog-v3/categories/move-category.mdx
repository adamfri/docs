    Moves a category within its parent category, or to a different parent category.

    <Note>

      **Authentication**

      You can only call this method when authenticated as a Wix app or Wix user [identity](https://dev.wix.com/docs/api-reference/articles/authentication/about-identities).

    </Note>

    ## Permissions

    This method requires one of the following permission scopes:

    <div className="wix-scopes">

    <span className="wix-scope" title="SCOPE.CATEGORIES.CATEGORY_WRITE">Category write</span>

    </div>

    Learn more about [app permissions](https://dev.wix.com/docs/build-apps/develop-your-app/access/authorization/about-permissions).

    Callable by: `APP`.

    ## Endpoint

    ```http
    POST https://www.wixapis.com/categories/v1/categories/{categoryId}/move
    ```

    ## Path Params

    <ParamField path="categoryId" type="string" required>

      ID of the category to move.

    </ParamField>

    ## Body Params

    <ParamField body="treeReference" type="TreeReference" required>

      Category tree reference details.

      <Expandable title="treeReference properties">

        <ParamField body="appNamespace" type="string" required>

          Namespace of the app whose catalog this category tree belongs to.

          Currently, only `"@wix/stores"` is supported.

          Constraints: `minLength 4`, `maxLength 150`.

        </ParamField>

        <ParamField body="treeKey" type="string">

          Key to differentiate between multiple trees managed by the same app.

          For Wix Stores, pass `null` or omit this field, as each store has only one category tree.

        </ParamField>

      </Expandable>

    </ParamField>

    <ParamField body="parentCategoryId" type="string">

      ID of the target parent category. Leave empty or omit to move the category to the top level.

    </ParamField>

    <ParamField body="position" type="string" required>

      Where to place the subcategory.

      + `FIRST`: Position the category as the first subcategory.
      + `LAST`: Position the category as the last subcategory.
      + `AFTER`: Position the category after the category ID passed in `moveAfterCategoryId`.

      **Supported values:**

      - `FIRST`
      - `LAST`
      - `AFTER`

    </ParamField>

    <ParamField body="moveAfterCategoryId" type="string">

      Required when passing `position: AFTER`.

    </ParamField>

    ## Response Object

    <ResponseField name="parentCategoryId" type="string">

      Parent category ID.

    </ResponseField>

    <ResponseField name="categoriesAfterMove" type="string[]">

      List of category IDs in the new order of arrangement.

      Constraints: `format GUID`, `maxItems 100`.

    </ResponseField>

    ## Errors

    | Status | Code | Application code | Description |
    | --- | --- | --- | --- |
    | `404` | `NOT_FOUND` | `PARENT_CATEGORY_NOT_IN_TREE` | Category's `parentCategoryId` must belong to the same tree as `treeReference`. |
    | `428` | `FAILED_PRECONDITION` | `CATEGORY_DEPTH_LIMIT_EXCEEDED` | Category depth exceeds the limit of 4 levels. |
    | `428` | `FAILED_PRECONDITION` | `TREE_CYCLE_DETECTED` | Cycles aren't allowed in the tree. |
    | `400` | `INVALID_ARGUMENT` | `MISSING_AFTER_CATEGORY` | The `moveAfterCategoryId` field must be provided when `position` is `AFTER`. |
    | `428` | `FAILED_PRECONDITION` | `AFTER_CATEGORY_NOT_IN_PARENT` | The category specified in `moveAfterCategoryId` must have the same `parentCategoryId` as the category being moved. |

    <Note>

      This method may also return standard errors. [Learn more about standard Wix errors](https://dev.wix.com/docs/rest/articles/getting-started/errors).

    </Note>

    ## Event Triggers

    This method triggers the following events:

    | Event | Type | Description |
    | --- | --- | --- |
    | Category Moved | `wix.categories.v1.category_category_moved` | Triggered when a category is moved to a different position or parent category. |
