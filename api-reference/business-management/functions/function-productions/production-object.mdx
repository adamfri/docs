A function production defines a function and its related entities.

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Function production ID. This is the same as the created function's ID.

      **Read-only.**

    </ResponseField>

    <ResponseField name="appId" type="string">

      App ID of the business solution that created the function type the function production is based on.

      Constraints: `format GUID`.

    </ResponseField>

    <ResponseField name="type" type="string">

      Type that the function is created from.

      **Supported values:**

      - `BLANK` — Function created from a function type.
      - `TEMPLATE` — Function created from a function template.

    </ResponseField>

            <ResponseField name="status" type="string">

              **Supported values:**

              - `INACTIVE` — Inactive. Inactive automations cannot be triggered.

            </ResponseField>

            <ResponseField name="trigger" type="Trigger">

              Trigger configuration.

              <Expandable title="trigger properties">

                <ResponseField name="appId" type="string">

                  ID of the app that defines the trigger.

                  Constraints: `format GUID`.

                </ResponseField>

                <ResponseField name="triggerKey" type="string">

                  Trigger key.

                  Learn about [setting up a trigger](https://dev.wix.com/docs/rest/business-management/automations/triggers/add-a-trigger-to-your-app#step-1--set-up-the-trigger).

                  Constraints: `minLength 1`, `maxLength 100`.

                </ResponseField>

                <ResponseField name="filters" type="Filter[]">

                  Schema field filters. All filter conditions must be met for the automation to run.

                  Learn more about setting up [automation filters](https://dev.wix.com/docs/rest/business-management/automations/automations/automations-v2/configure-your-automation#filters).

                  Constraints: `maxItems 5`.

                  _Nested structure omitted for brevity — see the `Filter[]` object._

                </ResponseField>

                <ResponseField name="scheduledEventOffset" type="FutureDateActivationOffset">

                  Automation offset. You can schedule automations to run before the trigger occurs.

                  Learn more about [scheduled events](https://dev.wix.com/docs/rest/business-management/automations/automations/automations-v2/configure-your-automation#scheduled-events).

                  _Nested structure omitted for brevity — see the `FutureDateActivationOffset` object._

                </ResponseField>

                <ResponseField name="overrideSchema" type="object">

                  Trigger schema override. When specified, this replaces the trigger schema.

                </ResponseField>

              </Expandable>

            </ResponseField>

            <ResponseField name="rootActionIds" type="string[]">

              Root action IDs. A root action is the first action that runs after the trigger occurs. Root actions run in parallel.

              > **Note**: You can currently only specify 1 root action.

              Constraints: `format GUID`, `maxItems 20`.

            </ResponseField>

            <ResponseField name="actions" type="object">

              Actions the automation can execute, as `key:value` pairs. For the key, specify the action ID. The value must be an object structured as described below.

              Constraints: `format map`.

              <Expandable title="actions properties">

                <ResponseField name="key" type="string" />

                <ResponseField name="value" type="Action">

                  _Nested structure omitted for brevity — see the `Action` object._

                </ResponseField>

              </Expandable>

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="origin" type="string">

          How the automation was added to the user's site.

          Constraints: `immutable`.

          **Supported values:**

          - `USER` — Created by a [Wix user](https://dev.wix.com/docs/build-apps/get-started/overview/glossary#wix-user).
          - `APPLICATION` — Created by a [Wix app](https://dev.wix.com/docs/build-apps/get-started/overview/glossary#wix-app) for a particular site.
          - `PREINSTALLED` — [Preinstalled automation](https://dev.wix.com/docs/build-apps/develop-your-app/extensions/backend-extensions/automations/pre-installed-automations/about-pre-installed-automations).

        </ResponseField>

        <ResponseField name="settings" type="AutomationSettings">

          Automation settings. Applied only for pre-installed and application automations. Not applied to User origin automations

          <Expandable title="settings properties">

            <ResponseField name="hidden" type="boolean">

              Whether the automation is hidden from users.

              Default: `false`

            </ResponseField>

            <ResponseField name="readonly" type="boolean">

              Whether the automation is read-only.

              When `true`, site owners can't modify the automation or any of its actions. When `false`, users can configure specific actions as skippable or read-only using `settings.actionSettings`.

              Default: `false`.

              > **Note**: Setting `readOnly` to `true` overrides `settings.actionSettings`.

            </ResponseField>

            <ResponseField name="disableDelete" type="boolean">

              Whether to disable the option to delete the automation from the site.

              Default: `false`.

            </ResponseField>

            <ResponseField name="disableStatusChange" type="boolean">

              Whether to disable the option to change the automation's `configuration.status`.

              Default: `false`.

            </ResponseField>

            <ResponseField name="actionSettings" type="ActionSettings">

              Automation action settings.

              <Expandable title="actionSettings properties">

                <ResponseField name="permanentActionIds" type="string[]">

                  IDs of actions whose `skipActionExpression` can't be modified.

                  An action's `skipActionExpression` determines whether the action is skipped. Including an action's ID in this array makes its `skipActionExpression` permanent, so it can't be changed.

                  When empty, the `skipActionExpression` of all actions can be edited.

                  Constraints: `format GUID`, `maxItems 30`.

                </ResponseField>

                <ResponseField name="readonlyActionIds" type="string[]">

                  IDs of read-only actions. Read-only actions cannot be modified.

                  When empty and the automation's `settings.readonly` is `false`, all actions are modifiable.

                  Constraints: `format GUID`, `maxItems 30`.

                </ResponseField>

              </Expandable>

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="draftInfo" type="DraftInfo">

          When the automation is a draft, the draft details.

          **Read-only.**

          <Expandable title="draftInfo properties">

            <ResponseField name="originalAutomationId" type="string">

              ID of the original automation.

              **Read-only.**

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="archived" type="boolean">

          Whether the automation is archived.

          To archive an automation, set this to `true`. To restore an archived automation, set this to `false`.

        </ResponseField>

        <ResponseField name="autoArchivePolicy" type="AutoArchivePolicy">

          Auto archive policy

          <Expandable title="autoArchivePolicy properties">

            <ResponseField name="archiveDate" type="datetime">

              Date when to archive the automation
              If this date in the past, nothing will happen (automation will not go into archived state)
              If this date in the future, on this date the automation will be updated with archived = true and configuration.status = INACTIVE
              After this date the automation may be unarchived and archived again, this date will have no influence

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

      **Read-only.**

    </ResponseField>

    <ResponseField name="updatedDate" type="datetime">

      Date and time the function production was last updated.

      **Read-only.**

    </ResponseField>
