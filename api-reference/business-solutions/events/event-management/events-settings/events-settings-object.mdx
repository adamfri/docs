---
title: "Events Settings Object"
description: "Events Settings reads the settings and state of a site's Wix Events & Tickets app."
icon: "cube"
---

Events Settings reads the settings and state of a site's [Wix Events & Tickets](https://www.wix.com/app-market/web-solution/events) app.

<Tabs>

  <Tab title="REST">

    <ResponseField name="id" type="string">

      Events Settings ID.

      **Read-only.**

    </ResponseField>

    <ResponseField name="createdDate" type="datetime">

      Date and time the Events Settings were created.

      **Read-only.**

    </ResponseField>

    <ResponseField name="updatedDate" type="datetime">

      Date and time the Events Settings were last updated.

      **Read-only.**

    </ResponseField>

    <ResponseField name="revision" type="integer">

      Revision number, which increments by 1 each time the Events Settings are updated. To prevent conflicting changes, the current revision must be passed when updating the Events Settings.

      **Read-only.**

    </ResponseField>

    <ResponseField name="siteInfo" type="SiteInfo">

      Site information including locale, language, and available premium features.

      **Read-only.**

      <Expandable title="siteInfo properties">

        <ResponseField name="locale" type="string">

          Site locale in IETF BCP 47 language tag format. For example, `en-US` for U.S. English.

          **Read-only.**

        </ResponseField>

        <ResponseField name="language" type="string">

          Site language in ISO 639-1 alpha-2 format. For example, `en`.

          **Read-only.**

        </ResponseField>

        <ResponseField name="premiumFeatures" type="string[]">

          Premium features available to the site. These features control access to advanced events capabilities. Use this array to determine which functionality to enable in your integration. For example, check for `SELL_TICKETS` before showing payment options.

          **Read-only.** Constraints: `maxItems 20`.

          **Supported values:**

          - `SELL_TICKETS` — Enables paid ticket sales for events. When present, the site can create paid ticket definitions and process payments through configured payment providers.
          - `INCLUDE_URL_IN_EMAIL` — Allows including custom URLs in event notification emails sent to attendees. Useful for adding registration links, additional information, or branded content in emails.
          - `HIDE_FOOTER_IN_EMAIL` — Removes Wix branding from event notification emails. Provides a fully customized email without Wix attribution in the footer.

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="eventsInfo" type="EventsInfo">

      Global information about the site's events, including whether any events have been created and current ticket sales status.

      **Read-only.**

      <Expandable title="eventsInfo properties">

        <ResponseField name="firstEventCreated" type="boolean">

          Whether the site has created its first event.

          **Read-only.**

        </ResponseField>

        <ResponseField name="sellingTickets" type="boolean">

          Whether any events on the site sell tickets, including both free and paid tickets.

          **Read-only.**

        </ResponseField>

        <ResponseField name="sellingPaidTickets" type="boolean">

          Whether any events on the site sell paid tickets specifically. Requires both ticket definitions with non-zero prices and the `SELL_TICKETS` premium feature.

          **Read-only.**

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="serviceFeeSettings" type="ServiceFeeSettings">

      Settings for Wix service fees applied to paid ticket sales.

      **Read-only.**

      <Expandable title="serviceFeeSettings properties">

        <ResponseField name="serviceFeeEnabled" type="boolean">

          Whether Wix service fees are applied to paid ticket sales.

          **Read-only.**

        </ResponseField>

      </Expandable>

    </ResponseField>

    <ResponseField name="paymentSettings" type="PaymentSettings">

      Payment configuration including available payment methods, coupon acceptance, and delayed capture settings.

      <Expandable title="paymentSettings properties">

        <ResponseField name="ticketSalesEnabled" type="boolean">

          Whether ticket sales are enabled for the site. Free ticket sales are always available; paid ticket sales require the `SELL_TICKETS` premium feature and configured payment providers.

          **Read-only.**

        </ResponseField>

        <ResponseField name="activePaymentMethods" type="PaymentMethod[]">

          Payment methods currently available for ticket checkout. Automatically populated based on the site's payment provider configuration. Common methods include credit cards, PayPal, and digital wallets.

          **Read-only.** Constraints: `maxItems 100`.

          <Expandable title="activePaymentMethods properties">

            <ResponseField name="methodId" type="string">

              Payment method identifier indicating the type of payment accepted. For example, `creditCard`, `payPal`, `applePay`, or `googlePay`. Use this to determine which payment options to display in checkout.

              **Read-only.** Constraints: `maxLength 20`.

            </ResponseField>

          </Expandable>

        </ResponseField>

        <ResponseField name="couponsAccepted" type="boolean">

          Whether discount coupons can be used during ticket checkout. Automatically enabled when at least one coupon exists on the site.

          **Read-only.**

        </ResponseField>

        <ResponseField name="giftCardsAccepted" type="boolean">

          Whether gift cards can be used during ticket checkout. Requires gift card functionality to be enabled at the site level.

          **Read-only.**

        </ResponseField>

        <ResponseField name="delayedPaymentCaptureSettings" type="DelayedPaymentCaptureSettings">

          Configuration for delayed payment capture, allowing payments to be authorized at purchase but captured later. This setting applies to all events on the site and can be updated through the API.

          <Expandable title="delayedPaymentCaptureSettings properties">

            <ResponseField name="enabled" type="boolean">

              Whether delayed payment capture is enabled for all ticket sales on the site. When enabled, payments are authorized at purchase but captured later.

            </ResponseField>

          </Expandable>

        </ResponseField>

      </Expandable>

    </ResponseField>

    ## Example

    <CodeGroup>

      ```json Object
      {
        "eventsSettings": {
          "id": "8046df3c-7575-4098-a5ab-c91ad8f33c47",
          "revision": 1,
          "createdDate": "2019-10-30T17:22:10.299Z",
          "updatedDate": "2019-10-30T17:22:10.299Z",
          "siteInfo": {
            "locale": "en-US",
            "language": "en",
            "premiumFeatures": ["SELL_TICKETS", "INCLUDE_URL_IN_EMAIL"]
          },
          "eventsInfo": {
            "firstEventCreated": true,
            "sellingTickets": true,
            "sellingPaidTickets": false
          },
          "paymentSettings": {
            "ticketSalesEnabled": true,
            "activePaymentMethods": [
              {
                "methodId": "creditCard"
              },
              {
                "methodId": "payPal"
              }
            ],
            "couponsAccepted": true,
            "giftCardsAccepted": false,
            "delayedPaymentCaptureSettings": {
              "enabled": false
            }
          }
        }
      }
      ```

    </CodeGroup>
